## 一、已处置

### T-20261109-02 重启后 web 页面等半天（I-20261109-01）→ 已完成

**不是服务端慢。** 实测把所有端点打了一遍：全链路 190ms，装配只 3.06s，accept 循环
每连接 `tokio::spawn`（无串行），Monaco 那 12MB 是懒加载、不占首屏。

**真因在启动器**：`run.cmd` 用 `cargo run`（先编译再启动），却固定 `timeout /t 4`
之后就开浏览器。实测编译耗时：

| 场景 | 耗时 |
|---|---|
| 全量重编 | 24.9s |
| 只改 agent-loop | 2.2s |
| 只改 host | 1.7s |
| 装配（bash沙箱+provider ping+技能预热） | 3.06s |

也就是说浏览器**总在编译期就打开**，白屏时长 = 编译时长。这解释了为什么「似乎之前
出现过」——只要改过代码，重启就必然复现；而没改代码时（增量 0s）感觉又正常。

**修法**：`scripts/wait-host-ready.ps1` 轮询 `GET /` 到 200 才开浏览器（上限 180s，
超时提示而非打开死页面）。留了个坑给后来者：内联 PowerShell 走 cmd 会被吞掉变量名
（实测 `$u`→空、`$r`→`ll`），必须落成独立 `.ps1`。

## 五、这轮改动的可复用结论

- **「慢」要先分清是服务慢还是没起来**：本轮 90% 的排查时间花在证明服务端 190ms，
  最后真因在启动器。教训是：先量「从触发到服务可响应」的端到端时间，再拆段。
- **能力与数据的宿主必须分开**：看板那次 bug 的根因是「工具在哪」和「数据在哪」被
  绑成同一个变量（`WORKSPACE_ROOT`）。分成 `RSI_HOME`（代码根）与 `WORKSPACE_ROOT`
  （数据）后，换工作区不再换掉能力。
- **cmd 批处理不适合内联 PowerShell**：`$` 变量会被吞，凡是超过一行的 PowerShell
  都应落成 `.ps1` 文件用 `-File` 调用。
