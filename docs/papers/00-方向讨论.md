## 1. 关键实测：R3 的"无损"是我们自己的说法，机器不认

对 29 个会话、20,009,987 字符 trace 逐字比对（探针 `.scratch/e7-fidelity.py`、`e7b-reconstruct.py`）：

| 层 | 内容 | 字符数 | 相对 traces | 能否重建压缩前工作集 |
|---|---|---|---|---|
| `traces/<id>.jsonl` | 全量事件（含 `result_truncated`） | 20,009,987 | 100% | 基准 |
| `events/<id>.jsonl` | append-only sidecar | 487,638 | **2.44%** | ❌ |
| `sessions/<id>.json` | 压缩后工作集 | 逐会话 10⁵ 量级 | — | 模型实际所见 |

sidecar 缺的重建字段（逐项检查全 MISSING）：

- 原消息全文（只存 `preview.slice(0,200)`）
- tool_call 参数
- tool_result 全文
- 消息顺序 id

**即：sidecar 是一条审计索引，不是一份可重放的日志。** 源码注释说"原文永不因压缩删除"——但实际保留的是**前 200 字符**。这不是 bug，是设计没跟上声称。

压缩事件本身的字段是完整的（`first_kept` / `kept` / `tokens_before` / `summary`），**边界知道，内容不在**。9 次压缩样本：

| # | tokens_before | kept | first_kept | summary 长度 |
|---|---|---|---|---|
| 1 | 761,547 | 30 | 604 | 1,764 |
| 2 | 271,480 | 30 | 110 | 1,033 |
| 3 | 95,869 | 30 | 49 | 847 |
| 4 | 270,225 | 30 | 169 | 2,154 |
| 5 | 170,492 | 30 | 151 | 1,369 |
| 6 | 63,790 | 30 | 19 | 1,035 |
| 7 | 167,239 | 30 | 145 | 1,450 |
| 8 | 238,393 | 29 | 219 | 1,238 |
| 9 | 65,962 | 29 | 35 | 1,354 |

**这组数据本身就是一个研究点**：压缩比最高一次是 761,547 → 摘要 1,764 字符，**约 432 : 1**；第二次压缩甚至从 110 条之前开始（`first_kept=110` 而 `kept=30`，说明两闸不一致又有残留）。

## 2. R3 改写后的新主张（这是论文 B 的核心）

不再说"无损"，改说**一个可机检的不变式缺失**：

> **`Reconstructibility Gap`**：现有 agent 记忆系统声称"日志为真相源"，但**没有任何系统同时做到 (a) 有损压缩、(b) 可从日志重建压缩前模型可见上下文、(c) 把 (b) 写成 runtime 可断言的检查**。我们把这个缺口形式化为一组可失败的断言，并在一个真实系统上测出缺口大小（2.44%）。

文献支撑（这是空白，逐条核过）：

- **ActiveGraph**（2026-05）：日志即真相源、确定性 replay，但作者自认**没有 compaction**（百万事件全量重放）；
- **pi**（仅文档）：有 compaction + 树 + fork，**没有任何 replay 保证、没有量化验收**；
- **E-mem**（ICML 2026）：保留未压缩上下文，但 reconstruction 是**语义级**；
- **Parallel Context Compaction**（2026-05）：只证明有损 + run-to-run 不可预测；
- **Replay Is a Family of Assertions**（2026-08）：把 replay 做成可证伪断言族（5,540 logs 实测），但**不含 compaction 场景**。

→ **"压缩 × 严格重放"的交叉点空着**，而且我们手上有 29 个真实会话、9 次压缩、2,221 次带 `memory_truncated` 标记的截断，可以直接给出**第一个缺口度量**。

## 3. K2 的收窄：从"审计信号"到"权限不对称"

`Audit Without Verification`(2026-09) 已实测：报告层 relay 而不 check，上游真错时误伤无辜方 **34.4% / 62.6%**，审计者只在 **4.1%** 情况下找回真实源头。**这是对"报告即信号"的负面结论，必须引用。**

我们的差异只有一个，但很硬：**我们的下游根本没权限改上游**（`CORE_PROTECTED` 实际拦截 5 次），所以不存在"顺手修掉"这个选项，缺陷必然上抛、且上抛带**可复算的归因链**（哪个 commit、哪次 e2e、哪个 K 错误码）。

这在结构上不同于 Audit Without Verification 的 6-agent 同构 relay：那里每个 agent 都能自己改；这里权限是**单向的**。

## 4. R1 的收窄：从"harness 影响成本"到"合同违约的类型学"

`What Does a Harness Buy? Tokens, Mostly`(2026-10) 已经说了 harness 决定账单（同模型同任务成本差 3×，差异由 system prompt + tool schema 前导决定）。**这条不能再当新贡献。**

我们能留下的是更窄但更硬的一层：**当环境违约（而非模型能力不足）时，模型的补偿行为可以被打成类型学，并折算成确定成本**。

实测（29 会话、5,368 次 bash）：

| 指标 | 值 |
|---|---|
| bash 调用总数 | 5,368 |
| 带 `cd` 前缀 | 3,760（**70.0%**） |
| `cd` 前缀消耗字符 | 201,868 / 1,261,369（**16.0%**） |
| 无前缀 bash | 1,608 |
| 其中失败 | 100（6.2%） |
| 单会话最高 | `s-mw28xsv9`：2,139/2,165（**98.8%**） |

根因链（一手证据）：

1. `host/src/instances.rs:171` — `WORKSPACE_ROOT` 直接取自 `ws.canonicalize()`；
2. Windows 上 `canonicalize()` 返回 `\\?\D:\...` 扩展长度前缀；
3. `instances.rs:44` 的注释确认团队知道此事（在 `remember_workspace` 里 strip），**但 spwan 子进程时没 strip**；
4. 后果（commit `02f78cf` 原文）：「D1 bash 在 `\\?\` 前缀工作区下**静默改在 `C:\Windows` 执行且 exit=0**」；
5. 模型的对策：每条命令自己加 `cd /d`。

**这就是"合同税"**：环境没履约，代价以 token 形式转嫁给模型，且**因为 exit=0，模型无法从返回值判断自己是否需要补偿**——只能永远补偿。

## 6. 效度威胁（两篇共用，进 Limitations）

1. 单机、单用户、Windows-only，无多 seed；
2. 全部数字自报，但**可由 git + trace 复算**（这是主要抗辩）；
3. bash 可替代率三快照分母不同，**不构成时间序列**；
4. 模型漂移真实存在（项目自己实现了 `E_LLM_DRIFT` 拒写基线）；
5. **闭环未在时间上收敛**：`active` 技能 0 个、账本 1 条工作记录 → 正文动词锁在 `we design / we implement`，**禁写** `we demonstrate that the system self-evolves`；
6. 居民只有 2 个（react-agent / mini-agent）；
7. 2.44% 保真率是**单一系统的一次测量**，不是跨系统 benchmark——论文 B 必须把自己定位成"提出缺口 + 首个度量"，不能写成"评测了 N 个系统"。
