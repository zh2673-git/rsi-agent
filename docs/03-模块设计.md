# 模块设计

> 本文给出 rsi-agent 的模块划分、接口契约与执行流；四层细节见 04/05。

## 1. 模块总览

| 模块 | 形态 | 职责 | 依赖 |
|---|---|---|---|
| `rsi-steward` | 技能（Markdown） | 判定模式、路由阶段、守住收敛 | creat-skill、skill-eval、project-dev |
| `skill-eval` | 技能（Markdown） | 案例设计、rubric、判分、基线 | 无 |
| `creat-skill` | 技能（vendored，优化） | 专业还原、契约、三级验收 | 无 |
| `project-dev` | 技能（vendored，优化） | 带工具技能的代码开发与测试 | tdd、repo-explorer |
| `skill_validate` | Python 工具 | 静态质量门 | 标准库 |
| `run_evals` | Python 工具 | 回放案例、输出 scorecard | 标准库；可选 LLM |
| `ledger` | Python 工具 | 记录/检索工作与经验 | 标准库 |
| `skill_ab` | Python 工具 | 同一 suite 的 A/B 对比（盲评 scorecard） | run_evals 产物 |
| `usage_report` | Python 工具 | 使用率/成功率统计、退役候选与执行 | ledger |
| `dashboard` | Python 脚本 | 生成只读静态看板 | usage_report、ledger |
| `rsi_routine` | Python 工具 | 外部信号扫描、复盘提案、审批队列 | ledger、config |
| `health_report` | Python 工具 | 月度技能库健康报告 | ledger、usage_report |
| `promotion` | 规则 + 文件状态 | 候选/生效/退役迁移 | validate、eval、ledger |

## 2. 模块 A：rsi-steward（生产线编排）

### 数据规范

输入任务卡：

```json
{
  "task_id": "work-20261031-001",
  "goal": "把一份英语单元练习改成适合分层作业的版本",
  "acceptance": ["每个层级的题目难度可解释", "覆盖本单元核心词汇", "教师可直接打印"],
  "signals": ["用户确认", "可打印检查"]
}
```

### 接口

- `load_skill("rsi-steward")`：获得流程与路由规则。
- `load_skill("creat-skill")`：当 Decide = 造/改。
- `load_skill("skill-eval")`：当进入 Validate/Evaluate。
- `load_skill("project-dev")`：当技能带可执行工具。
- `skill_validate` / `run_evals` / `ledger_*`：工具调用。

### 执行流

```text
Intake → Recall → Decide ─┬─ 复用 → Execute
                         └─ 造/改 → Author → Validate → Evaluate → Execute
Execute → Verify → Retro → Promote
```

### 关键规则

1. **Recall 优先**：先查 active 技能与账本；能复用就不造。
2. **Decide 门槛**：重复出现 ≥2 次，或判断密度高、可复用时才造；否则直接做。
3. **单点改动**：一次只改一层（认知/工具/流程），避免无法归因。
4. **外部信号**：没有用户确认、测试、eval 或真实结果，停在 candidate。

## 3. 模块 B：skill_validate（静态门）

### 接口

```powershell
python scripts/skill_validate.py --skill skills/<name> --json
```

输出：

```json
{
  "ok": false,
  "skill": "demo",
  "errors": [
    {"code": "E_ACCEPTANCE_MISSING", "path": "SKILL.md", "message": "缺少验收段"},
    {"code": "E_REF_MISSING", "path": "SKILL.md#L12", "message": "引用的 references/x.md 不存在"}
  ],
  "warnings": [
    {"code": "W_NO_EVALS", "message": "未提供 evals/cases.jsonl，最多停留在 draft"}
  ]
}
```

### 检查项（P0）

| 检查 | 规则 | 级别 |
|---|---|---|
| 目录名 | 等于 frontmatter `name`，kebab-case | error |
| description | 含触发词，长度在预算内 | error |
| references | 所有引用存在；无孤儿文件 | error |
| 验收段 | 存在「验收/成功标准」段落 | error |
| 状态 | `draft/candidate/active/retired` 之一 | error |
| 案例 | candidate/active 至少 3 条 | error |
| 来源 | 理论规则有来源等级与校验信号 | warning（active 前升级为 error） |
| 体量 | SKILL.md 行数 ≤ 预算（默认 120 行） | warning |

## 4. 模块 C：run_evals（评测器）

### 接口

```powershell
python scripts/run_evals.py --skill skills/<name> --suite evals/cases.jsonl --baseline ledger/baseline.json --json
```

输出 scorecard：

```json
{
  "skill": "demo",
  "version": "0.2.0",
  "suite": "default",
  "cases": [
    {"id": "c1", "pass": true, "score": 1.0, "signal": "assert"},
    {"id": "c2", "pass": false, "score": 0.4, "signal": "judge", "reason": "缺少分层依据"}
  ],
  "summary": {"pass_rate": 0.6, "regression": false, "new_fix": true},
  "promotion": {"eligible": false, "reason": "旧案例 c3 退化"}
}
```

### 执行器

| 技能类型 | 执行方式 | 判分 |
|---|---|---|
| 工具型 | 直接跑工具/断言 | 确定性 |
| 知识型 | subagent 按案例执行 | rubric + 另一个模型/人工 |
| 混合型 | 工具结果 + 文本产物 | 两部分加权 |

### 规则

- 基线是「当前 active 版本」的分数；没有基线先跑一次建立基线。
- 晋升条件：新问题修复 + 旧案例不退化 + 触发测试通过。
- 同模型自评只能作为 `partial` 信号，不能单独触发 active。

## 5. 模块 D：ledger（工作账本）

### 记录

```json
{
  "work_id": "work-20261031-001",
  "created_at": "2026-10-31T10:00:00+08:00",
  "goal": "分层作业改编",
  "acceptance": ["...", "..."],
  "skills_used": ["rsi-steward@0.1.0", "creat-skill@0.3.0"],
  "outcome": "success",
  "signals": [{"type": "user_confirm", "value": true}, {"type": "eval", "value": 0.8}],
  "cost": {"rounds": 12, "tokens": 38000},
  "decision": "reuse",
  "artifacts": ["outputs/分层作业.docx"],
  "lessons": [{"type": "failure_fix", "skill": "creat-skill", "summary": "先写验收再写正文"}]
}
```

### 接口

```powershell
python scripts/ledger.py append --file ledger/work/2026-10/work-001.json
python scripts/ledger.py query --skill creat-skill --signal failure_fix --limit 5
```

### 规则

- 字段白名单；不写对话全文、不写密钥、不写个人信息。
- 查询结果按「任务相似度 + 技能 + 信号类型」排序，默认最多 5 条。
- 账本不自动注入上下文；由 rsi-steward 在 Recall 阶段按需召回。

## 6. 模块 E：promotion（晋升/回退）

### 状态机

```text
draft ──validate──> candidate ──eval+signal──> active ──low usage/fail──> retired
   ^                    │                         │
   └────── abort ◀──────┘                         └── rollback ──> 上一 active
```

### 迁移规则

| 迁移 | 条件 | 动作 |
|---|---|---|
| draft → candidate | validate 通过 + ≥3 案例 | 写 `state.json`，候选不进目录 |
| candidate → active | 不退化 + 新问题修复 + 外部信号（E1/E2/E3） | 记录 scorecard、替换 active、旧版留档；改工具/核心仍人工确认 |
| candidate → draft | eval 退化 | 保留失败证据 |
| active → retired | 连续 N 次失败或 30 天零使用 | 移出目录，保留目录归档 |
| active → 上一版 | 线上回归失败 | 回滚并写账本 |

### 接口

Phase 1 做 capability 接缝；Phase 2 用文件 + 规则实现业务：

```powershell
python scripts/skill_state.py promote --skill demo --version 0.2.0 --evidence ledger/evidence/demo-0.2.0.json
```

## 7. 模块 F：预置技能包

| 技能 | 状态 | 说明 |
|---|---|---|
| `rsi-steward` | 新建 draft | 生产线编排；须先过 validate |
| `skill-eval` | 新建 draft | 评测方法；自带案例模板 |
| `creat-skill` | vendored + 优化 | 增加 evals/skill.json 要求 |
| `project-dev` | vendored + 优化 | 增加「技能开发」路由与 run_evals 对位 |

## 8. 外部技能接入（import adapter）

现有技能不需要改原目录，接入 rsi-agent 时做三件事：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 导入 | 复制/挂载到 `skills/{name}/`；从 frontmatter 生成 `skill.json` | 得到标准目录 |
| 标注 | 无 evals → `verification: unverified`；有 evals → 跑一次建基线 | `legacy` / `candidate` |
| 进化 | 补验收与案例 → validate → candidate → 外部信号 → active | 进入 RSI 闭环 |

规则：

- `legacy` 技能**可直接使用**，但不能自动晋升；使用结果写账本。
- 原目录保持只读；所有改造发生在 rsi-agent 的 vendored 副本。
- 接入适配器只做「结构转换」，不重写技能内容；内容优化走 creat-skill 的存量优化。

## 9. 执行流时序（一次造技能）

```text
1. 用户请求
2. rsi-steward: Recall 查 active 技能与账本
3. Decide: 记录「造/不造」理由 → 账本
4. creat-skill: 还原 + 契约
5. 写 skills/{name}/SKILL.md + references + evals
6. skill_validate: 失败 → 修；通过 → state=candidate
7. run_evals: 基线对比 → 通过则进入执行
8. 用技能完成任务 → Verify 核对验收标准
9. Retro: 失败/修正 → failure-fix 写回 registry
10. Promote: 外部信号（E1/E2/E3）→ active；否则保持 candidate
```

**任何一步失败都回到上一步或 Abort；不允许跳过 validate/evals 直接 active。**

## 10. 对比、退役与例行复盘（Phase 3/4）

### 对比

```text
A scorecard（active） ┐
B scorecard（candidate）┴→ skill_ab → 逐案例 diff → promote / reject / hold
```

判分盲评：judge 只接收 `{case, output}`；A/B 结论不替代晋升闸门。

### 退役

```text
usage_report（ledger + state + eval） → 退役候选（dry-run）
   → --apply --yes → skill_state retire → feedback.jsonl
   → 恢复：retired → draft（证据保留）
```

### 例行复盘

```text
rsi_routine scan（用户修正/连续失败/评测退化/周期/配额超限）
   → trigger → proposal（baseline + scorecard + rollback_point）
   → knowledge + E1/E2/E3 + eligible → 自动批准
   → tools/core 或 E5 → approve --human
   → 批准 ≠ 生效：仍走 creat-skill → validate → eval → promote
```

月度 `health_report` 汇总状态、失败、候选与提案；`dashboard` 生成只读 HTML 快照，二者都不改技能。
