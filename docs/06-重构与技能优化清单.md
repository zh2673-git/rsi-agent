# 重构与技能优化清单

> 原则：内核少改、执行体只改接缝、技能层把「散文」变成「可执行标准」。
> 优先级：P0 不做就无法闭环；P1 提升质量与效率；P2 等真实需求。

## 1. agent-kernel（只改一处，明确三不做）

### P0：conformance 作为「生成代码工具」的准入门

- **现状**：内核已有 conformance 套件，用于插件出生证明；但 rsi 产出的代码工具走 `tools.json` 直接安装，没有准入检查。
- **改动**：在 `skill_install` / 工具安装管线中，若工具带可执行体（Python/TS/Rust 插件），先跑 conformance 或等价的最小契约测试，通过才允许 `active`。
- **不改内核代码**：复用现有 conformance；由 rsi-agent 的安装脚本调用。
- **验收**：故意破坏契约的工具被拒；正常工具不受影响。

### 明确不做

| 项 | 理由 |
|---|---|
| 内核感知技能/评测/账本 | 违反「内核只做时空管家」的边界 |
| 多 provider 路由/负载均衡 | 无真实居民需求；技能层 A/B 用评测器即可 |
| 事件总线持久化 | 证据归 rsi-agent 的账本，不归内核 |
| 技能包管理器 | 轻资产原则；版本用快照 |

## 2. react-agent（只改三个接缝）

### P0-1：host 装配可注入（为发行形态留口）

- **现状**：[main.rs](../react-agent/crates/host/src/main.rs) 硬编码 spawn 顺序与插件列表。
- **改动**：抽出 `HostSpec`（插件清单、路径、开关）与 `assemble_with(spec)`；默认 spec 保持现有行为。
- **收益**：rsi-agent 不必复制宿主；后续可做独立发行二进制。
- **兼容**：默认路径零变化；现有 e2e 不改。
- **验收**：`cargo test` 全绿；默认启动行为一致。

### P0-2：assets 增加技能校验/状态钩子

- **现状**：[assets_plugin.py](../react-agent/plugins/assets/assets_plugin.py) 负责技能 CRUD 与 load；但写入后不做质量检查。
- **改动**：新增 `skills.validate` 与 `skills.state` capability；`skill_install` 前调用并返回结构化错误。
- **注意**：Phase 1 直接做 assets 校验/状态钩子；外部脚本只用于工具型与批量检查，不要维护两套真相。
- **验收**：坏技能不会被安装为 active；错误可定位。

### P0-3：agent-loop 增加两个默认关闭的策略钩子

- **现状**：[agent-loop](../react-agent/crates/agent-loop/src/lib.rs) 是纯 ReAct 循环；没有「先写验收」与「完成前核对」。
- **改动**：
  1. `contract_first`：非平凡任务在首个工具调用前要求一份验收清单（可落 todo）。
  2. `verify_before_final`：最终答复前检查验收清单是否逐条核对；未核对返回提醒。
- **默认关闭**：由 rsi-agent 的配置开启，保持通用性。
- **验收**：关闭时行为零变化；开启时缺验收的任务会被拦截。

### P1：经验召回 capability

- 新增 `experience.query`（或薄工具）按技能/任务召回账本摘要；不塞进 `memory.session`。
- **理由**：账本是跨会话情景记忆，和会话记忆的生命周期不同。

### 明确不做

| 项 | 理由 |
|---|---|
| 把 RSI 策略写死进 agent-loop | 破坏通用性；应由技能/配置驱动 |
| 新 ReAct 引擎 | 重复建设 |
| 技能包管理器 | 同 assets PLAN 结论 |

## 3. creat-skill（从方法论升级为可执行标准）

| 优先级 | 改动 | 落点 | 验收 |
|---|---|---|---|
| P0 | 新增 `evals/` 与 `skill.json` 产物要求 | [SKILL.md](../creat-skill/SKILL.md)、[07-封装规范](../creat-skill/references/07-封装规范.md) | 产物缺案例/契约即 validate 失败 |
| P0 | 三级验收改为「可执行判据」：L1 自检、L2 subagent 盲跑、L3 外部信号 | [05-验收与沉淀](../creat-skill/references/05-验收与沉淀.md) | 每级有明确通过条件与记录字段 |
| P0 | 增加「值不值得造」门槛（Decide） | SKILL.md 第 0 节 | 一次性任务不产技能 |
| P1 | 理论锚点强制三元组：来源等级 → 规则 → 校验信号 | [03-转译三桥](../creat-skill/references/03-转译三桥.md) | active 前缺三元组即不合格 |
| P1 | 存量优化增加「基线/回归/回退」 | [06-存量优化](../creat-skill/references/06-存量优化.md) | 每次改动有 scorecard 与决策 |
| P2 | 模板增加 `skill.json` / `cases.jsonl` 骨架 | [templates](../creat-skill/templates) | 新建技能可直接通过 validate |

**注意**：creat-skill 仍是「方法论技能」，不新增代码；具体执行交给 `rsi-steward` 与工具。

## 4. project-dev（补一条路由，不重写）

| 优先级 | 改动 | 落点 | 验收 |
|---|---|---|---|
| P0 | 增加「技能开发」作为一类项目：产物是 `skills/{name}/`，验收走 creat-skill 的 evals | [SKILL.md](../project-dev-skill/skills/project-dev/SKILL.md) 模式判定表 | 带工具的技能能正确路由到 tdd |
| P1 | 明确 `run_tests`（代码）与 `run_evals`（技能）对位 | 同上 §8 | 两类工作都有验证执行器 |
| P1 | 优化模式支持技能目录内的 `PLAN.md` | §6 | 技能改版有演进轨迹 |
| P2 | 不新增 skill 专用命令 | — | 保持轻量 |

**边界**：project-dev 负责「有执行体的技能」；纯认知技能由 creat-skill + skill-eval 负责。

## 5. 预置技能包

| 技能 | 来源 | 优先级 | 要点 |
|---|---|---|---|
| `rsi-steward` | 新建 | P0 | 召回→判定→生产→校验→评测→执行→复盘→晋升；只编排不实现 |
| `skill-eval` | 新建 | P0 | 案例设计、rubric、判分、基线、盲评 |
| `creat-skill` | vendored + 优化 | P0 | 加 evals/skill.json；三级验收可执行 |
| `project-dev` | vendored + 优化 | P1 | 加技能开发路由 |

预置策略：

- **vendored**：复制到 `rsi-agent/skills/`，允许 RSI 版本独立演进；上游更新时人工合并。
- `config/skills.lock.json` 记录来源与版本，避免「不知道这份是哪版」。
- 不建技能市场、不做远端依赖解析。

## 6. 工具清单

| 工具 | 优先级 | 形态 | 说明 |
|---|---|---|---|
| `skill_validate.py` | P1 | Python 标准库 | 静态检查，JSON 输出；与 assets 钩子同源 |
| `run_evals.py` | P1 | Python 标准库 + 可选 LLM | 案例回放、scorecard、基线对比 |
| `ledger.py` | P1 | Python 标准库 | append/query，字段白名单 |
| `skill_state.py` | P1 | Python 标准库 | 状态迁移、快照、回退 |
| `conformance_gate.py` | P1 | 调用内核套件 | 生成代码工具准入 |

## 7. 改动顺序（避免双写）

1. Phase 1 先做 Rust 接缝：host 装配 spec → assets 校验/状态 → agent-loop 策略钩子。
2. 接缝保持默认关闭/默认行为不变，`cargo test` 全绿后才进入业务闭环。
3. Phase 2 再铺脚本工具（validate/eval/ledger）与预置技能；能复用 capability 就不做第二套。
4. 内核只在「生成代码工具准入」时接入，不扩语义。

## 8. 验收

- **P**：现有 react-agent 测试、内核 conformance 全绿。
- **Q**：三个 skill 的优化项都有对应判据；工具 CLI 可独立运行。
- **I**：没有新增包管理、数据库、第二个运行时；核心代码只在约定接缝改动。
