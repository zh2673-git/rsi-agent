# rsi-agent 项目方案

> 生产模式文档 | 版本 v0.1（待确认） | 对应 `program.md`
> 目标运行体：react-agent v0.1.21 + agent-kernel v0.1.7

## 项目目标

让一个通用 agent 能在真实工作中形成 **可复现、可回退、可积累** 的自我改进闭环：
先判断值不值得造技能，再按 creat-skill 生产技能，用客观案例评测，按基线晋升或回退，并把结果沉淀为下一次可检索的经验。

它解决的问题不是「agent 会不会写技能」，而是：

1. 写出来的技能**凭什么算合格**；
2. 新版本**凭什么比旧版本好**；
3. 一次成功/失败**凭什么能变成下一次的能力**。

## 本质定义

**rsi-agent 是一个「技能生产与晋升的发行形态」：在通用 agent 执行体之上，增加一条有验收、有证据、有状态机的技能生产线。**

- 它不是内核：不管理插件空间、不调度执行流。
- 它不是通用 agent：不重复实现 ReAct、工具、记忆。
- 它的核心资产是：**技能契约、评测案例、工作账本、晋升规则**。

### 时空契约校验

| 维度 | 契约 |
|---|---|
| **空间归属** | `skills/` 由 assets capability 单写；`ledger/` 由 rsi 账本工具单写；会话 trace 归 memory 所有；`workspace/` 归 tools 所有。跨域只读，不直接改对方内存/文件。 |
| **时间流形态** | 外层是**状态机**（10 个阶段，离散迁移）；内层是 agent-loop 的 **ReAct 循环**（受轮次与预算约束）。晋升是状态迁移，不允许跳步。 |
| **规则拦截** | 写技能 → `skill_validate` 静态拦截；进候选 → `run_evals` 评测；晋升 → 外部信号（E1/E2/E3）自动；改工具/核心 → 人工确认；运行期 → 沙箱/超时/轮次上限。 |

### 本质竞品锚定

| 竞品 | 本质（推断） | 时空差异 | 本项目选择 |
|---|---|---|---|
| Voyager（技能库式智能体） | 把可执行代码存成技能，成功后追加 | 空间：代码片段库；时间：试错循环；规则：执行成败 | 我们存「认知 + 工具 + 案例」，并加静态门与晋升状态 |
| AutoGen / CrewAI | 多智能体编排 | 空间：角色消息；时间：对话循环；规则：角色契约 | 我们不做角色编排，先用 subagent 做「同行盲评」 |
| DSPy 式自动优化 | 用指标驱动 prompt/程序搜索 | 空间：程序参数；时间：优化循环；规则：指标 | 我们用「案例 + rubric + 基线」做小样本优化，不做大规模搜索 |
| Cursor Rules / Claude Skills | 目录 + 说明文件的轻资产 | 空间：文本资产；时间：模型按需加载；规则：无强制验收 | 保留轻资产，但强制契约、案例、状态与回退 |

**锁定定义**：轻资产技能（目录 + Markdown + 可选工具），重验收（案例 + 评分 + 状态机），不重平台。

## 架构总览（第0级时空映射）

rsi-agent 是发行形态而非代码工程，因此第0级映射按「产品资产」而非「运行时代码」落位：

| 时空层级 | 本项目对应 | 物理目录 | 核心职责 |
|---|---|---|---|
| 数据规范（规则） | 契约 schema、阈值、状态 | `policies/`、`config/` | 定义技能/案例/账本的字段与合法状态 |
| 数据存储（空间） | 账本、案例、快照 | `ledger/`、`skills/*/evals/` | 证据与案例持久化 |
| 流转-规则（业务时空） | 技能生命周期 | `skills/*/skill.json`、`state.json` | draft/candidate/active/retired |
| 流转-编排（调度时空） | RSI 工作流 | `skills/rsi-steward/` | 召回→判定→生产→校验→评测→执行→复盘→晋升 |
| 运行时（时空管家） | react-agent host | 外部 `react-agent/crates/host` | 插件生命周期、ReAct 循环、Web/CLI |
| 数据接口（时空入口） | 技能加载、工具调用 | `load_skill`、`tools` | 模型与用户触发的入口 |

**依赖铁律**：

- rsi-agent 不反向依赖 agent-kernel 的内部类型；只通过 react-agent 的 capability。
- 技能不直接写账本；账本不直接改技能状态；状态迁移必须经过晋升规则。
- 核心代码（`agent-kernel/`、`react-agent/crates/`）只读。

## 模块递归四层设计

### 模块 A：技能生产线（rsi-steward）

- 本质：在「通用 agent 执行体」约束下，本模块是**把需求转成可验收技能的状态机**。
- 数据规范：`skill.json`、`SKILL.md` frontmatter、`evals/cases.jsonl`、`state.json`。
- 数据存储：`skills/{name}/` 目录；版本历史用快照/`registry`，不做包管理。
- 数据流转：Intake → Recall → Decide → Author → Validate → Evaluate → Execute → Verify → Retro → Promote。
- 数据接口：`load_skill("rsi-steward")` + `skill_validate` / `run_evals` / `ledger_*` 工具。
- 生命周期：由 agent-loop 按任务触发，无独立进程；终止于 Promote 或 Abort。

### 模块 B：验证门（skill_validate）

- 本质：技能进入候选态前的**静态规则拦截器**。
- 数据规范：错误码、字段路径、严重级别。
- 数据存储：无持久化，只读技能目录。
- 数据流转：扫描目录 → 解析 frontmatter → 校验引用/预算/验收段 → 返回结构化结果。
- 数据接口：`skill_validate(name)`；`skill_install` 前置调用。
- 生命周期：每次写入/安装时调用，失败即拒绝。

### 模块 C：评测器（run_evals）

- 本质：把「技能好坏」从主观判断变成**案例回放 + 基线对比**。
- 数据规范：case、rubric、scorecard、baseline。
- 数据存储：`evals/results/{version}.json`、`ledger/baseline.json`。
- 数据流转：加载案例 → 执行技能 → 判分 → 与基线比较 → 输出 scorecard。
- 数据接口：`run_evals(skill, version, suite)`。
- 生命周期：候选态与晋升前调用；失败不自动重试超过 N 次。

### 模块 D：工作账本（ledger）

- 本质：把一次任务变成**可检索的情景记忆**，而不是聊天记录。
- 数据规范：work_id、任务、验收标准、技能、结果、信号、成本、决策。
- 数据存储：`ledger/work/{yyyy-mm}/{work_id}.json` + 索引。
- 数据流转：任务开始写 plan → 执行中追加步骤 → 结束写 verdict → 失败触发 retro。
- 数据接口：`ledger_append`、`ledger_query(skill|task|signal)`。
- 生命周期：按需读写，不常驻上下文。

### 模块 E：晋升与回退（state machine）

- 本质：技能的**版本闸门**。
- 数据规范：`draft → candidate → active → retired`；`version`、`parent`、`score`、`signals`。
- 数据存储：`skills/{name}/state.json`（或 `skill.json.status`）。
- 数据流转：validate 通过 → candidate；eval 不退化 + 外部信号 → active；退化 → 回退上一版。
- 数据接口：`skill_promote` / `skill_rollback`（Phase 1 先落 capability 接缝，Phase 2 用文件工具 + 规则实现）。
- 生命周期：晋升/退役事件写账本。

### 模块 F：预置技能包

| 技能 | 来源 | 职责 |
|---|---|---|
| `rsi-steward` | 新增 | 生产线编排与值不值得造的判定 |
| `skill-eval` | 新增 | 案例设计、判分、基线对比 |
| `creat-skill` | 现有，优化后 vendored | 专业还原、契约、三级验收 |
| `project-dev` | 现有，优化后 vendored | 带工具技能的执行层开发与测试 |

## 验证方式

### P（前置）

`react-agent-host` 可启动；`SKILLS_DIR` 可写；厂商 key 可用；基线快照存在；Python 标准库可用。

### Q（后置）

- 坏技能被拦截；
- 低分候选不晋升；
- 一次真实失败能产出 failure-fix 且下一次可召回；
- 一次真实任务产出完整账本。

### I（不变量）

- react-agent 测试零回归；
- 内核零改动；
- 技能仍是轻资产；
- 账本无密钥/隐私；
- 状态机无死循环，任务有预算上限。

### L（协同 LLM 维度）

- 技能描述可被模型正确触发（触发测试 ≥ 90%）；
- 加载后模型能复述验收标准；
- 评分器与人工判断偏差在可接受范围（首版只做小样本一致性检查）。

## 项目愿景

1. **v0.1 可验收**：技能有契约、案例、状态，坏技能进不来。
2. **v0.2 可积累**：账本与 failure-fix 能在下一次任务中被召回。
3. **v0.3 可对比**：候选 vs 生效的 A/B 评测与看板。
4. **v0.4 可退役**：低使用率/低成功率技能自动降级，控制技能库膨胀。
5. **长期**：RSI 从「人工触发的改进」走向「有外部信号触发的例行复盘」，但晋升始终保留人类闸门。
