# 实施路线与验收

> 原则：先接缝、再闭环、后扩能力；每个 Phase 都有可观察的验收，不通过不进入下一阶段。

## Phase 0：契约冻结（已完成）

### 交付物

- [x] `program.md`（生产模式，关键决策已确认）
- [x] 架构、模块、生产线、评测/记忆、重构清单
- [x] 用户确认 5 个决策项（账本默认 `rsi-agent/ledger/`，`RSI_LEDGER_DIR` 可覆盖）

### 验收

- 5 个决策项全部有明确结论；
- 三方关系（kernel/react-agent/rsi-agent）无歧义；
- P/Q/I 具体值可执行。

## Phase 1：Rust 接缝（已完成）

### 交付物

1. [x] `react-agent` host 抽出 `HostSpec` / `assemble_with(spec)`；默认 spec 与现有行为一致。
2. [x] assets 增加 `skills.validate` 与 `skills.state`（draft/candidate/active/retired）；`skill_install` 前置调用。
3. [x] agent-loop 增加两个**默认关闭**的策略钩子：`contract_first`、`verify_before_final`。
4. [x] 生成代码工具的 conformance 准入钩子（`scripts/conformance_gate.py` 调用现有套件，不改内核代码）。
5. [x] 兼容导入适配器（`scripts/import_skill.py`）：从现有 frontmatter 生成 `skill.json`，缺案例标 `unverified/legacy`。

### 验收

- `cargo test` 全绿；默认启动与现有 e2e 行为零变化。
- 坏技能被 assets 拦截，错误包含 `code/path/message`。
- 策略钩子关闭时不改变任何行为；开启时缺验收的任务被拦截。
- 契约被破坏的生成工具无法进入 active。
- 不新增第三方 crate。

### 回退条件

- 接缝改动影响默认行为 → 立即回退，改为 feature flag 隔离。
- assets 校验无法满足 → 退回脚本实现，并在 PLAN 记「已评估不做」。

## Phase 2：生产线闭环（已完成）

### 交付物

1. [x] `rsi-agent/skills/` 预置六个技能：新建 `rsi-steward`、`skill-eval`；vendored `creat-skill`、`project-dev` 及其依赖 `repo-explorer`、`tdd`。均为 `draft`，legacy 技能标 `legacy: true`。
2. [x] `scripts/skill_validate.py`、`run_evals.py`、`ledger.py`、`skill_state.py`（另含 `conformance_gate.py`、`import_skill.py`、共享 `rsi_common.py`）。
3. [x] `policies/` 下的 schema 与晋升规则。
4. [x] `config/rsi.toml` 阈值 + `config/skills.lock.json` 来源锁定。
5. [x] 用 `react-agent-host` + `SKILLS_DIR` 跑通一次真实任务（单轮实测：技能目录六项全部注入，两个策略钩子保持关闭）。

### 实现要点

| 任务 | 说明 | 验收 |
|---|---|---|
| skill_validate | 目录名/描述/引用/验收段/案例/状态 | 坏技能被拒，JSON 错误定位 |
| run_evals | 支持 assert 与 judge 两种 case | 同版本重复结果稳定 |
| ledger | append/query，字段白名单 | 召回 ≤5 条，不返回全文 |
| rsi-steward | 十阶段流程与 Decide 门槛 | 一次性任务不造技能 |
| skill-eval | 案例/rubric/基线规范 | 新技能能写出 3 条案例 |
| import adapter | 现有技能转标准目录 | legacy 可用、不可自动晋升 |

### 验收场景

1. 新建一个故意缺验收段的技能 → validate 拒绝。
2. 候选技能分数低于基线 → 不晋升，记录原因。
3. 一次真实失败 → 生成带 case_id 的 failure-fix。
4. 下一次同类任务 → Recall 命中该经验。
5. 账本写入 → 不含对话全文/密钥/个人信息。
6. 一个现有技能导入 → 标 legacy，可直接调用但不自动晋升。

### 回退条件

- 任一场景失败 → 修脚本或修技能，不进入 Phase 3；
- 若脚本工具无法通过 `tools.json` 安装 → 回到 Phase 1 的 assets 钩子。

## Phase 3：对比与退役（已完成）

### 交付物

1. [x] 候选 vs active 的 A/B 评测（同一 suite、逐案例 diff）：`scripts/skill_ab.py`；judge 只收 `{case, output}`，盲评。
2. [x] 技能使用率/成功率统计（来自账本）：`scripts/usage_report.py`。
3. [x] 低分/零使用技能退役规则：`config/rsi.toml [retire]`；`--apply --yes` 批量执行，退役后可回 draft。
4. [x] 只读看板：`scripts/dashboard.py` 生成 `dashboard/index.html`（技能状态、评测分、使用率、最近失败、提案）。不新增 Web 路由，遵守 react-agent 接缝纪律。

### 验收

- A/B 结果可复现（同一份 scorecard 输入 → 同一结论）；
- 退役不误伤（默认 dry-run；`--yes` 才执行；`retired → draft` 可恢复）；
- 看板数据与账本/技能目录一致（每次生成重读，不缓存）。

## Phase 4：例行化 RSI（已完成）

### 交付物

1. [x] 外部信号触发的例行复盘：`scripts/rsi_routine.py scan`（用户修正 / 连续失败 / 评测退化 / 周期复盘）。
2. [x] 技能改版分层：知识层凭 E1/E2/E3 + scorecard 自动批准；工具/核心层必须 `approve --human`。
3. [x] 例外审批队列：`rsi_routine.py queue|approve|deny`，提案落 `ledger/proposals/`。
4. [x] 月度技能库健康报告：`scripts/health_report.py` → `ledger/reports/YYYY-MM.md|json`。
5. [x] 技能库配额告警：`[quota]`（max_active/max_total）超限时 `rsi_routine.py scan` 产生 `quota/E5` 触发，健康报告标记超限。

### 验收

- 无外部信号的改版不会自动批准（E5 只能 `--human`）；
- 每个提案都有 baseline、scorecard、rollback_point；
- 技能库规模受控：`[quota]` 超限只告警与复盘触发，不自动删技能；退役候选与提案在报告中集中呈现。

## 全局 P/Q/I

### P

- `react-agent-host` 启动成功；
- `SKILLS_DIR` 可写、`ledger/` 可写；
- LLM provider 可用；
- baseline 存在。

### Q

| 场景 | 通过标准 |
|---|---|
| 坏技能 | validate 拒绝，错误定位到字段 |
| 低分候选 | 不晋升，原因入账本 |
| 真实失败 | 生成 failure-fix，有 case_id |
| 下一次任务 | Recall 命中，且上下文只增摘要 |
| 一次完整任务 | 产出账本 + 验收核对 + 决策 |
| A/B 退化 | `skill_ab` 结论 reject，旧案例 pass→fail 可定位 |
| 无外部信号提案 | 不自动批准（E5 需 `--human`） |
| 退役 | 默认只出候选；`--apply --yes` 后 retired，可回 draft |

### I

- react-agent 测试零回归；
- agent-kernel 零改动；
- 技能仍是轻资产；
- 账本无敏感信息；
- 状态机有最大尝试次数与预算上限；
- 核心文件只读。

## 风险清单

| 风险 | 表现 | 对策 |
|---|---|---|
| 自评闭环 | 模型自己写、自己判、自己晋升 | 外部信号 + 盲评 + 高风险人工确认 |
| 评测成本高 | 每条任务都跑案例 | 小样本（3-10 条）；只在候选/晋升时跑 |
| 技能膨胀 | 每个任务都造技能 | Decide 门槛 + 使用率统计 + 退役 |
| 上下文污染 | 召回整本账本 | 只返回摘要与路径；默认 ≤5 条 |
| 过度工程 | 一开始就做插件/DB/图引擎 | Phase 1 接缝优先；脚本按需；不建新运行时 |
| 版本分叉 | vendored 技能与上游漂移 | `skills.lock.json` + 定期人工合并 |
| 规则被绕过 | 直接写文件改状态 | 状态迁移只走 `skill_state`；validate 前置 |

---

## 完成定义（DoD）

rsi-agent v0.1 完成，当且仅当：

1. 一个真实任务可以完整走完十阶段，并留下账本；
2. 一个坏技能进不来，一个低分候选升不上去；
3. 一次失败能变成下一次可召回的经验；
4. 全程未修改 agent-kernel，react-agent 仅在约定接缝改动（或零改动）；
5. 所有产物仍是「目录 + Markdown + JSON」，无新增服务。
