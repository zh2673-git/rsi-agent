# 评测与记忆四层设计

> 范围：模块 C/D。评测解决「怎么算变好」，账本解决「怎么把一次工作变成下一次的经验」。

## 1. 评测系统（run_evals）

### 1.1 本质

用**有限案例的回放与基线对比**，把「技能好坏」从主观判断降为可观察事实；不追求统计显著，只追求「不退化 + 修好新问题」。

### 1.2 数据规范

| 数据 | 字段 | 约束 |
|---|---|---|
| case | id/input/expect/rubric/signal/weight/source | 至少 3 条；signal ∈ assert/judge/human/test |
| rubric | 维度/权重/通过标准/反例 | 权重和 = 1 |
| scorecard | case 结果/summary/promotion | 每次评测一份 |
| baseline | skill/version/pass_rate/case_scores | 每个 active 版本一份 |

### 1.3 数据存储

```text
skills/{name}/evals/results/{version}.json
ledger/baseline.json
ledger/evidence/{name}/{version}/scorecard.json
```

### 1.4 数据流转

```text
load cases → 逐条执行 → 判分 → 汇总 → 对比 baseline → 输出 promotion 建议
```

执行器选择：

| 类型 | 执行 | 判分 | 说明 |
|---|---|---|---|
| 工具型 | 调用工具/脚本 | assert | 确定性，优先 |
| 知识型 | subagent 新会话执行 | rubric + 另一模型 | 避免同上下文污染 |
| 混合型 | 工具产物 + 文本 | 加权 | 两部分独立评分 |

### 1.5 数据接口

```powershell
python scripts/run_evals.py --skill skills/demo --suite evals/cases.jsonl --baseline ledger/baseline.json --json
```

返回 `scorecard`，并写 `evals/results/{version}.json`。

### 1.6 判分纪律

1. **基线先建**：active 技能首次评测即基线；无基线不比较。
2. **案例不随版本改**：修 bug 可以加案例，但不能删旧案例；删除需在账本记原因。
3. **同模型不单独裁决**：E5 只能作为提示，不能进入 promotion 条件。
4. **盲评**：judge 不暴露「这是新版本/旧版本」，只给案例与产物。
5. **失败要可复现**：每条失败必须能定位到 case id 与产物路径。

### 1.7 阈值（首版）

| 指标 | 门槛 |
|---|---|
| 新问题案例 | 必须从 fail → pass |
| 旧案例 | 不允许 pass → fail |
| 触发测试 | ≥ 90%（10 条真实话术） |
| 总分 | 不低于基线 - 0.05 |
| 抽检 | 可选：每周抽 1 条，不阻塞自动晋升 |

## 2. 工作账本（ledger）

### 2.1 本质

一次任务的**情景记忆**：做了什么、为什么这么做、结果如何、用户怎么反馈。它不是聊天记录，不参与默认上下文。

### 2.2 数据规范

```json
{
  "work_id": "work-20261031-001",
  "task": "分层作业改编",
  "acceptance": [{"id": "a1", "text": "...", "checked": true}],
  "skills": [{"name": "rsi-steward", "version": "0.1.0"}, {"name": "creat-skill", "version": "0.3.0"}],
  "steps": [{"phase": "Decide", "choice": "create", "reason": "同类任务第 2 次"}],
  "outcome": "success",
  "signals": [{"type": "user_confirm"}, {"type": "assert", "value": true}],
  "cost": {"rounds": 12, "tokens": 38000, "duration_s": 420},
  "decision": "promote",
  "lessons": [{"type": "failure_fix", "skill": "creat-skill", "case_id": "c4", "summary": "先写验收再写正文"}],
  "artifacts": ["outputs/分层作业.docx"]
}
```

字段白名单：禁止对话全文、密钥、令牌、学生/家长个人信息。

### 2.3 数据存储

```text
ledger/
├── work/2026-10/work-20261031-001.json
├── index.jsonl                 # 轻索引：work_id/task/skills/outcome/signals
├── baseline.json
├── evidence/{skill}/{version}/
└── feedback.jsonl              # 用户修正/回滚事件
```

### 2.4 数据流转

```text
任务开始 → 写 plan（acceptance）
执行中 → 追加 phase/step（可选）
结束 → 写 outcome + signals + cost + lessons
失败/返工 → 生成 failure-fix → 写回技能 registry
查询 → 按 skill/task/signal 召回 ≤5 条
```

### 2.5 检索规则（Recall）

| 查询 | 排序 | 返回 |
|---|---|---|
| 同类任务 | 技能重合 + 文本相似 + 时间近 | 3 条摘要 + 路径 |
| 某技能失败 | case_id + 时间近 | 5 条 failure-fix |
| 用户修正 | 最近 30 天 | 3 条原话摘要（脱敏） |

**不返回完整记录**，只返回摘要、关键结论与文件路径；需要细节时再读文件。

### 2.6 记忆边界

| 记忆 | 归属 | 生命周期 | 是否进上下文 |
|---|---|---|---|
| 工作记忆 | `memory.session` + todo | 会话 | 是 |
| 情景记忆 | `ledger/` | 跨会话 | 按需 |
| 程序记忆 | `skills/` | 长期 | 渐进披露 |
| 语义记忆 | `skills/*/references` | 长期 | 按需 |

原则：**会话只带当前任务；经验按需召回；技能先看目录再加载全文**。

### 2.7 使用统计与健康报告（Phase 3/4）

| 产物 | 来源 | 用途 |
|---|---|---|
| `usage_report.py` | 账本 index + skill state + 最近 scorecard | 使用次数、成功率、连续失败、退役候选 |
| `rsi_routine.py` | 账本信号 + scorecard + review 事件 | 触发复盘、生成提案、审批队列 |
| `health_report.py` | 上述两者 | 月度报告（状态分布、失败、候选、提案） |
| `dashboard.py` | 同上 | 只读 HTML 快照（不启动服务、不改技能） |

统计口径：使用 = 账本记录中 `skills` 含该技能；成功 = `outcome=success`；连续失败 = 按时间排序的尾部 `fail` 计数。退役与提案只做候选/批准，实际改动仍回到 skill_state 迁移。

## 3. 复盘（retro）

### 3.1 触发

- 用户修正了输出；
- 测试/评测失败；
- 同一任务返工 ≥2 次；
- 用户显式说「记住这个」。

### 3.2 产出

1. **failure-fix**：现象 → 根因 → 修正 → case_id；
2. **exemplar**：好片段 → 为什么好 → 可复用结构；
3. **decision**：改技能 / 只记经验 / 不改。

### 3.3 规则

- 没有 case_id 的 failure-fix 不算沉淀，不能进入下一次回归。
- 一次 retro 只改一个技能的一层。
- 修改后必须重新 validate + eval；不允许只写 registry 不验证。

## 4. 验收（本模块）

- **P**：案例文件可解析；baseline 存在；账本目录可写。
- **Q**：同版本重复评测结果稳定；低分候选被拦截；失败案例可复现；召回 5 条内命中相关经验。
- **I**：评测不改技能内容；账本不含敏感字段；查询不返回全文；无外部服务依赖。
