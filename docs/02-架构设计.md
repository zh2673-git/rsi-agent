# 架构设计

> 目标：说明 rsi-agent 与 agent-kernel、react-agent 的关系，给出被否决方案与理由，明确目录、技术选型与改造接缝。

## 1. 三层关系

| 层 | 项目 | 本质 | 不应该做什么 |
|---|---|---|---|
| 运行时 | agent-kernel | 空间/时间/规则管家：插件空间、调度、契约、conformance | 不理解「技能」「评测」「经验」；不承载业务语义 |
| 执行体 | react-agent | 通用 agent：ReAct、工具、资产、记忆、Web | 不内置 RSI 策略；不强制所有用户使用技能生产线 |
| 发行形态 | **rsi-agent** | 技能生产线 + 评测/证据 + 晋升策略 + 预置技能 | 不复制 ReAct 引擎；不直接操作内核内部类型 |

**为什么不是「在 agent-kernel 上直接创建」**

- 内核只提供插件装配与调度；没有 LLM 适配、工具协议、会话、技能加载。
- 直接建在 kernel 上意味着重新实现 react-agent 的 `agent-loop`、`tools`、`assets`、`memory`、`host`，重复且会分叉。
- RSI 的改进单元是「技能」，而内核的改进单元是「插件」；语义层级不同，硬塞会污染内核边界。

**为什么不是「改造 react-agent 成为 rsi-agent」**

- react-agent 是通用执行体，应保持通用；RSI 是产品策略，不是所有 agent 用户的默认行为。
- 发行形态便于独立演进技能与策略，不绑定通用宿主版本。

## 2. 被否决方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 新建独立 Rust host，复制 spawn 逻辑 | 否决（Phase 1） | 与 react-agent host 重复；后续再抽装配 spec |
| 技能包管理器（版本求解/依赖/远端） | 否决 | 违背「目录 + SKILL.md」轻资产；assets PLAN 已裁定不做 |
| 内核内置技能生命周期 | 否决 | 内核应保持通用；技能是资产，不是运行时对象 |
| 图/工作流引擎做编排 | 否决 | 组合技能 + 顺序状态机已够；图引擎成本高、收益未证 |
| 全自动晋升 | 部分采纳 | 知识层：外部信号 E1/E2/E3 自动晋升；工具/核心层：保留人工确认 |
| 同模型自评驱动晋升 | 否决 | E5 只能作提示，不能进入晋升条件 |
| 数据库存账本 | 否决（Phase 1） | JSON/JSONL 足够；避免新服务与新依赖 |

## 3. 数据流

```text
用户请求
  → react-agent-host
      → agent-loop（ReAct）
          → assets.load_skill("rsi-steward")
          → tools: skill_validate / run_evals / ledger_*
          → llm-adapter / web / memory
      → agent-kernel（插件注册、调度、trace）
  → 产物
      → skills/{name}/（技能 + 案例 + 状态）
      → ledger/（工作账本）
      → memory.session.trace（会话事件）
```

**边界规则**：

1. `skills/` 的唯一写入者是 assets capability（以及人）；账本工具只读技能、只写账本。
2. `ledger/` 的唯一写入者是账本工具；agent-loop 通过工具调用，不直接写文件。
3. `memory.session.trace` 是会话事实源；账本是任务事实源；两者不复制整段对话。
4. 内核事件只用于可观测性，不作为 RSI 的长期证据库。

## 4. 目录规划

### 4.1 产品资产目录（Phase 2 实装）

```text
rsi-agent/
├── program.md
├── README.md
├── docs/
├── policies/
│   ├── skill-contract.schema.json
│   ├── eval-case.schema.json
│   ├── ledger.schema.json
│   ├── lifecycle.md
│   └── promotion.md
├── config/
│   ├── rsi.toml              # 阈值、最大尝试次数、路径
│   └── skills.lock.json      # 预置技能与版本
├── skills/
│   ├── rsi-steward/
│   ├── skill-eval/
│   ├── creat-skill/
│   └── project-dev/
├── ledger/                   # 运行时生成，gitignore
└── scripts/
    ├── skill_validate.py
    ├── run_evals.py
    └── ledger.py
```

### 4.2 与 react-agent 的接缝（Phase 1 实施）

| 接缝 | 现状 | 扩展 |
|---|---|---|
| host 装配 | `main.rs` 硬编码 spawn 顺序 | 抽出 `HostSpec` / `assemble_with(spec)`，允许发行版注入插件与配置 |
| assets | 技能 CRUD + load | 增加 `skills.validate` / `skills.state` capability，或保持文件级 |
| agent-loop | ReAct 循环 | 增加「契约先行」「完成前核对」两个策略钩子（可选，默认关闭） |
| tools | 已含 todo / run_tests | 新增 rsi 工具时优先走 `tools.json`，不急着做插件 |
| kernel | conformance 套件 | 生成的可执行工具装载前跑 conformance |

## 5. 技术选型

| 选择 | 理由（时空视角） |
|---|---|
| 复用 react-agent host | 空间：不新开进程模型；时间：沿用现有 ReAct 主循环；规则：沿用内核契约 |
| Phase 1/2 用 Python 薄工具 | 空间：脚本即工具，无新插件空间；时间：同步调用，易调试；规则：输入输出 schema 校验 |
| JSON / JSONL 存证 | 空间：文件即证据，可 diff、可回滚；时间：追加写，天然审计；规则：schema 可校验 |
| git 快照 / 文件历史 | 复用现有版本能力，不造版本解析器 |
| 小样本评测（3-10 例） | 空间与时间成本可控；规则：只看「不退化 + 修好新问题」 |

## 6. 执行流模式

**外层状态机**（rsi-steward）：

| 状态 | 进入条件 | 产物 | 退出 |
|---|---|---|---|
| Intake | 新需求 | 任务卡 | Recall |
| Recall | 已有技能/账本 | 候选技能与经验摘要 | Decide |
| Decide | 候选不足 | 造/不造 决策 + 理由 | Author 或 Execute |
| Author | 决定造/改 | 契约 + 技能文件 + 案例 | Validate |
| Validate | 文件完成 | 校验报告 | Evaluate 或 Abort |
| Evaluate | 校验通过 | scorecard + 基线对比 | Execute 或 Abort |
| Execute | 技能可用 | 任务结果 | Verify |
| Verify | 结果产生 | P/Q/I 核对 | Retro |
| Retro | 有失败/修正 | failure-fix / exemplar | Promote |
| Promote | 信号成立 | 状态迁移 + 账本 | 结束 |

**内层 ReAct 循环**：每个状态内的工具调用由 agent-loop 驱动，受 `max_rounds` 与预算约束；状态机本身不递归。

## 7. 关键不变量

1. 没有 `skill.json` 的技能不能进 candidate。
2. 没有至少 3 条案例的技能不能晋升。
3. 没有外部信号的技能最多到 `candidate`。
4. 低分不覆盖高分：晋升只看「修复新问题 + 旧能力不退化」。
5. 任何状态迁移都写账本；账本是唯一审计入口。

## 8. Phase 2 文件落点

| 能力 | 落点 | 说明 |
|---|---|---|
| 生产线编排 | `skills/rsi-steward/SKILL.md` | 只写方法论与路由，不含代码 |
| 评测方法 | `skills/skill-eval/SKILL.md` | 案例格式、判分、基线规则 |
| 静态校验 | `scripts/skill_validate.py` | 纯标准库，stdout 返回 JSON |
| 评测执行 | `scripts/run_evals.py` | 先支持确定性断言与人工/LLM 判分 |
| 账本 | `scripts/ledger.py` | append/query，字段白名单 |
| 策略 | `policies/*.md` + `config/rsi.toml` | 阈值与状态机 |

**Phase 1 先做 Rust 接缝（host spec / assets 校验与状态 / agent-loop 策略钩子），默认行为保持不变**；Phase 2 再铺技能生产线与薄工具。
