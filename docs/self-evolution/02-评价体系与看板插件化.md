# C 轮：评价体系、引用装载、同类归纳、受约束的插件化看板

> 承接 **B 轮**（`docs/self-evolution/01-单会话与任务看板.md`：单会话形态 + 任务/灵感看板）。
> 用户构想里当时刻意留下的三块重活——「好坏标准（评价体系）」「人力选型真正生效」
> 「同类任务的总结归纳」「插件化的动态 UI 但要有约束」——本轮按可验证的边界逐个落地。
>
> 一句话本质：**B 轮把「任务」提升为一等对象，C 轮让这个对象可以被证明、被引用、被归纳、被装配。**

## 0. 本质定义（先契约后代码）

| 问题 | 回答 |
|---|---|
| 本质 | B 轮的看板只能说「我要做什么」；C 轮补的是「做完了没」「以前怎么做的」「界面由谁决定」三件。核心动作是**把「我说做完了」换成「跑给你看」**。 |
| 空间归属 | 一切仍在 `WORKSPACE_ROOT/.rsi/board.json` 单写点。新增两类字段（`checks`/`evaluation` 挂在任务上，`layout` 挂在板根），不新建文件、不新建目录。 |
| 时间流形态 | 评价是**一次性执行、结论留存**：`eval` 跑一次写 `verdict + 每条 evidence`，之后每轮 prompt 只读结论。布局是**声明式配置、渲染时求序**：文件里的顺序无关，kind 顺序钉死。 |
| 规则拦截 | ① `checks` 的 kind 封闭（cmd/file/grep/manual）、`timeout_secs` 1..600；② `verdict` 封闭（none/pending/pass/fail）；③ 检查失败时 `verifying/done` **自动退回 `doing`**；④ `layout.sections` ≤6 且 id≤24 唯一、kind/group_by/filter/metrics 全封闭；⑤ 章节顺序由 kind 重排，不信文件顺序。 |

**本轮不做的事（防重复尝试）**：不做沙箱白名单（`cmd` 就是工作区里跑命令，agent 本来就有 bash——问题不是权限而是证据）；不做「每轮把看板塞 prompt」（改为按需 `digest`/引用装载，带硬上限）；不做拖拽排布（用户明确「要有约束」）；不新增 SSE 事件类型（评价变化是分钟级，轮询够）。

## 1. 四块能力

### C1 评价体系：`checks` 是证据，`acceptance` 是标准

| 层 | 内容 |
|---|---|
| 数据 | `task.checks[] = {id, kind, name, target, timeout_secs?, status, evidence?, last_run?}`；`task.evaluation = {verdict, ran_at, pass, fail, skip, note}` |
| 执行 | `python scripts/board.py eval <ID> [--only c1,c2]`；四种 kind：`cmd`（exit 0 = pass，cwd=工作区）、`file`（存在性）、`grep`（纯 Python 子串扫描，不依赖 PATH 里的 findstr）、`manual`（**永远 skip**，待人判——agent 不能给自己判过） |
| 闸门 | ① `checks` 非空却 `verdict≠pass` 就 `done` → **warning**（自证不是证据）；② `eval` 出 `fail` 且任务在 `verifying/done` → **自动退回 `doing`**（假完成必须退回执行） |
| 可见 | 任务行加 verdict 徽章（通过/不通过/待人判）；详情展开列出每条检查 + `exit=`/`hits=`/`存在于否` + pass/fail/skip 汇总 |

**为什么 `manual` 永远 skip**：把「用户点头」这种条目交给 agent 自评，等于把验收体系的作用抵消。写 `skip` 让「有人要判」这件事在界面上显形，而不是伪装成 pass。

### C2 引用装载：`@T-…` / `@I-…` 是输入，不是待办

- `agent-loop/src/board_ctx.rs::refs_context` 在**组装 system prompt 时**就读看板，把被引用的任务（目标/计划/验收/检查结论/人财物/产物）与灵感（原文/标签/被哪些任务采纳）拼进去。
- 三种结局都明确：命中 → 装载；**全部未命中 → 只回报「stale @-reference」**（空壳 header 比不注入更误导）；无引用 → 空串。
- `board.py resolve "<text>"` 是同一套解析的 CLI 形态，供「间接拿到的文本」（排队消息、文件内容）使用。
- **为什么不让模型自己 `show`**：引用是输入的一部分；多引用时模型要 N 次工具往返才看见自己刚引用的东西。

### C3 同类归纳：`digest` 是按需检索，不是常驻上下文

- `python scripts/board.py digest [--skill <name>] [--status ..] [--limit N] [--brief] [--with-inspirations]`
- 输出：任务最小信息面（id/title/status/progress/skills/model/effort/verdict/检查数）+ `by_skill` 聚合（每个技能的总/在进行/已完成）。
- **无引用但本轮像「交代一件成规模的事」**时，prompt 里退化为**在办任务摘要**（≤12 条，done/cancelled 排除）——让模型先知道自己手上有哪些活。闲聊轮次零注入。

### C4 受约束的插件化看板：`layout.sections`

```
tasks（任务章节）    group_by: status|priority|skill  filter: all|open|done  limit: 1..200
metrics（指标章节）  metrics: by_status|by_skill|verdict|acceptance
inspirations（灵感章节）
```

- **插件化**：加一个章节 = 改 `layout.sections`（`board.py layout --file` 或 `POST /api/board {op:"layout.set"}`），前端不改代码。
- **有约束**：kind 只有三类、参数是封闭枚举、`id` ≤24 且唯一、最多 6 章，且**渲染顺序由 kind 钉死**（tasks → metrics → inspirations）——配置文件写乱序也改变不了结构。
- 前端 `app-board.js` 改为**布局驱动**：`#board-sections` 容器 + `boardSections()`（二次校验 + 排序）+ 三个渲染器。章节容器取代了原来写死的两个 section。
- `metrics` 章节回答的是本轮最该被看见的问题：**「有多少活没跑过验收」**（未跑/通过/不通过 + 有标准/有检查的比例）。

### 5.5 过程中的四个坑（留档防复现）

1. **补丁锚点互吞，把 `layout.set` 分支改成半截**。为修一个 `unreachable pattern` 警告连续加了三四个「删重复分支」补丁，每个新补丁的锚点都定义在上一版的残骸上，最终 `board.rs` 只剩半截分支（`cargo check` 报 `unexpected closing brace`）。**处置**：`git checkout` 回 HEAD，删掉全部临时补丁，把改动**重新拆成不重叠的 C1–C8**（每个补丁的锚点都在 HEAD 原文里且互不相交），一次重放即干净。
   **教训**：修「重复」不要用「再打一个补丁去删」——重复本身就是前一批补丁锚点重叠造成的，应该回到基线重新分组。
2. **多测共享进程环境变量**：C 轮第一版测试用 `set_var("WORKSPACE_ROOT")` 测 `refs_context`，与既有 `self_extension_section_gated_by_workspace_reachability` 串扰（后者断言 `C:\ws`），实测红。
   **处置**：把 `board_ctx` 拆成**纯函数渲染**（`render_refs(user_text, &board)`）+ **I/O 入口**（`refs_context`），测试只喂 `json!({...})`，不再碰环境。这也让代码更清楚：渲染逻辑不该知道文件在哪。
3. **`board.rs.patchbak` 是共享的**：同一文件多条补丁共享一份备份，`--revert` 会回到**首补丁之前**。本轮误把 `board.rs` 恢复到某个中间态时，靠 `git show HEAD:` 才拿到真正的基线（`.patchbak` 已被覆盖）。
   **处置**：改 `runtime/` 文件前先确认 `git status` 干净，基线以 git HEAD 为准；`.patchbak` 只当回滚锚点，不当真相。
4. **`--dry-run` 说 DRY、实跑却说 FAIL**：干掉 `patch_in_src` 幂等判据后，删除型补丁（`patch` 为空/极短）每次都要靠锚点命中；只要前一个补丁改动了锚点上下文，后一个就 FAIL。
   **处置**：删除型改动的 `patch` 一律写一句**占位注释**（不写空串），让幂等判据有事可依；并且删除块整块搬运、不手工重排。
