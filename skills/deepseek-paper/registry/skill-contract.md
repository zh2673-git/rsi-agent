# 技能契约 — deepseek-paper

> creat-skill 第 1 步要求：「判定结果必须写进契约，它决定后面工件的形态」。
> 本文件是 v0.1.0 的**补记**：技能是先按 DeepSeek 语料反推目录、后补契约的。凡属补记而非当时判定，标「补记」。

## 1 本质

| 项 | 内容 |
|---|---|
| 这类工作的本质 | 把「项目里发生过的事」转成「审稿人能复算的账」。不是写得像，而是每个数字都能追到出处 |
| 成功 = | 读者沿账本可复算正文每一个数字；找不到一处无 artifact 支撑的比较级；失败申报与局限各带机制解释 |
| 失败 = | ① 措辞像、数字假（本技能首次尝试即此，见 §7）；② 门禁全绿但论证缺席（§5.1 第三条实测） |
| 一句话排除的错误做法 | **先写正文再找数字**——写作阶段自由取材，必然选出「手边刚好有的那个数」 |

## 2 模式与算子

| 项 | 内容 |
|---|---|
| 成熟度 | **A 为主判**（学术出版：作者 / 审稿人 / 领域主席 / 文字编辑 / 读者，有明确打回与裁决）+ **B 为风格层**（「DeepSeek 报告怎么写」无公开分工，只能靠 20 篇语料取证，见 `registry/ds-corpus-evidence.md`） |
| 主算子 | **流水线**（六道工序，顺序不可跳） |
| 为什么选它 | 这类工作最怕**体裁随证据量反向选择**：先收料再挑体裁，一定挑「料刚好够」的那个。顺序固定才能把 provenance 变成前置条件而不是事后补丁 |
| 为什么不用角色制 | 单 agent 下「作者 → 审稿人 → 编辑」退化为自我复读：同一模型扮演审稿人不会打回自己的稿；且审稿是回合制的，一次性成稿没有回合 |
| 为什么不用决策树 / 递归 | 骨架由体裁唯一确定（T/M/A/S 四选一），不存在需要分支拆解的不确定性；递归会引入无谓深度 |
| 档位 | **标准档**（A 类 / 长期重复 / 单元 6 个 / 工件 7 个 / 三级验收）。偏差：references 6 篇 > 3–5 建议值，理由是六篇各回答一个互不可省的问题（体裁 / 骨架 / 措辞 / 证据 / 图表 / 质检），合并任两篇都会让路由表失去唯一性 |

## 3 单元（六道工序，无纯协调单元）

| 单元 | 做什么 | 判据 | 交付物 | 失败信号 |
|---|---|---|---|---|
| 1 定体裁 | T/M/A/S 四选一 | 有无对照实验、是否要为整个系统报全账 | 体裁字母 + 骨架清单 | 要报全账却选 M；设独立 Related Work 却选 T |
| 2 建证据账本 | `evidence_scan` 出骨架，人补 claim/value/scope | 每条 `status: ok` 且有 `source` | `02-证据账本.json` | 正文有数字，账本该条仍 `todo` |
| 3 挖研究点 | 五条挖掘线各轮一遍 | 能写成 `<机制名>: <收益>`，且每线 ≤1 主点 | 研究点清单 | 挖出 ≥3 个「主研究点」；写不出双段式小节名 |
| 4 搭骨架 + 写 | 按 `references/02` 逐章填必写件 | 每章都有账本条目支撑 | `04-论文.md` 草稿 | 某章无证据 → 回工序 2，不许硬写 |
| 5 出图表 | `paper_table` / `paper_figure` 生成 | 无手抄数字 | `tables/*.tex`、`figures/*.png` | 表里数字与正文不一致；图表未被正文引用 |
| 6 机检 + 移交 | `paper_lint` + 人工评分 | G1–G12 全绿 且 评分 ≥14/20 | `lint-report.json`、`06-评分.md` | 任一 FAIL 仍交付；只跑门禁不打分 |

## 4 理论锚点（理论 → 规则 → 校验信号）

| 理论 | 来源等级 | 推出什么规则 | 校验信号 |
|---|---|---|---|
| 预期违背：技术报告的「新」必须由对照体现，不能由形容词体现 | 二级（行业惯例 + 20 篇语料频次） | 无 artifact 的主张只能写 `we design / adopt`，禁止比较级 | G12 + 禁用词表；`outperforms` 类断言必须逐条有 compare 证据 |
| 测量学：可复算的数字只应有一个来源 | 一级（可复算性） | 表内数字一律由 `data/*.json` 经 `paper_table` 生成 | 同一数字出现在两处手写位置即回退 |
| 逻辑：必要 ≠ 充分 | 一级 | 门禁只能作下限，交付另需 10 项人工评分 | 门禁全绿后仍须 ≥14/20；坏稿曾被误判 PASS 的负例已入回归 |
| 体裁契约：三类体裁的章节份额由语料统计决定，不由个人偏好决定 | 二级（20 篇语料） | T/M 类不设独立 Related Work（A 类除外）；M 类必须设 `Unsuccessful Attempts` | G7 / G9 |

**冲突裁决优先级**（两个都对时选哪个）：可追溯性 > 修辞效果 ｜ 体裁契约 > 个人偏好 ｜ 评分 > 门禁（全绿 ≠ 可交）。

## 5 工件（每个都有消费方，无装饰工件）

| 工件 | 人读 / 机读 | 消费方 | 校验方式 |
|---|---|---|---|
| `01-素材卡.md` | 人读 | 工序 2、3 | 字段齐全，无空格 |
| `02-证据账本.json` | 机读 | 工序 4 取数、`paper_lint` G12 | `status=ok` 且 `verify` 可复算 |
| `03-大纲.md` | 人读 | 工序 4 | 每章挂到账本 id |
| `04-论文.md` | 人读 | 工序 6、下游打包 | `paper_lint` |
| `figures/` `tables/` | 机读产物 + 人读 | 正文引用 | 工具生成、无手改痕迹 |
| `lint-report.json` | 机读 | 交付判定 | `verdict` + `failed[]` |
| `06-评分.md` | 人读 | 交付判定 | 10 项 ≥14/20 |

## 7 沉淀

| 项 | 内容 |
|---|---|
| 失败-修正对（≥1） | `registry/failure-fixes.md` 11 条，每条带 case_id |

## 8 边界

| 项 | 内容 |
|---|---|
| 不做什么 | 不写博客 / 周报 / README；不替用户补实验或造消融；不做期刊 LaTeX 排版与投稿系统操作 |
| 下游是谁、交什么工件 | 投稿打包 / arxiv 上链：交 `04-论文.md` + `tables/*.tex` + `figures/*.png`；配图视频交 `make-video`，交带 `Figure N` 编号的图清单 |
| 何时不该触发 | 已给完整 LaTeX 只要润色（直接改）；只要摘要一段（直接套 `templates/03`）；只要格式转换 |
