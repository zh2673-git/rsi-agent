# pc-perf-doctor — 电脑性能诊断

## 何时用 / 何时不用

**用**：用户报告卡顿、风扇狂转、内存占用高、想看整体健康度、怀疑某进程吃资源。
**不用**：蓝屏/硬件故障/驱动崩溃（转专业工具）；应用功能 bug（转对应工程技能）；纯网络测速。

**第一原则**：先测后断。任务管理器/性能滴表的"占用率"是**累积值或瞬时快照**，不能直接当结论。风扇响的真因要靠**短时间 CPU 增量**定位，不是看谁 WS 大。

## 三步法（每次都走）

### 第 1 步：采基线（先量化，不猜）
跑 `scripts/collect.py`（Windows，纯标准库 + PowerShell），一次拿到：
- 内存总量 / 空闲 / 已用（提交内存），算占用率；
- 整机 CPU 负载；
- 进程数；
- Top N 进程（工作集 WS、私有字节 PM、累计 CPU）。

脚本只读，不改系统、不杀进程。

### 第 2 步：定真因（增量 > 快照）
对可疑进程跑 `scripts/collect.py --delta <PID> 3`，取 **3 秒 CPU 增量**：
- 增量 ≈ 秒数 → 单核满载（约 100% 一个核心），是风扇元凶；
- 增量 ≈ 0 → 只是历史累计高/内存大，不是当前消耗。

判据与常见误判见 `references/diagnosis.md`。

### 第 3 步：归因分级 + 给方案
按 `references/evidence.md` 给每条结论标证据等级：
- E1 实测（有增量/指标数字）；
- E2 代码/配置确认（有文件行号）；
- E3 推测（无硬证据，必须直说）。

只针对 E1/E2 的项给优化动作，**E3 不触发改动**。给动作前过一遍 `references/safety.md`：不杀用户/外部进程，不把 Windows 缓存当泄漏。

## 输出结构（每次交付固定四段）
1. **实测数据表**：把 collect.py 的数字列出来，不修饰；
2. **结论**：一句话——正常 / 有异常，异常具体是哪个进程；
3. **分级证据**：每条结论标 E1/E2/E3；
4. **建议**：只列有证据支撑的动作，标"需用户确认"的项。

## 验收标准
一次诊断合格，当且仅当：
1. 报告含 collect.py 的实测数字（内存/CPU/增量），不是凭印象；
2. 每条结论标了 E1/E2/E3，E3 没有当结论或触发动作；
3. 风扇类问题给出单进程 CPU 增量数据，未只用 WS/累计 CPU 下判断；
4. 结尾声明"未杀用户进程、未重启机器"；
5. 优化动作做完有回归验证（重测指标）。
