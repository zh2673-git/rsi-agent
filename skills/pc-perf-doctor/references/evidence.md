# 证据分级

> 一条结论必须带等级。没有硬证据的结论不许写成"事实"，更不许据此动手改系统。

| 等级 | 含义 | 例子 | 能否触发优化动作 |
|---|---|---|---|
| **E1** | 实测数字，可复现 | "PID 19656 3 秒 CPU 增量 3.06s" | 可以 |
| **E2** | 代码/配置确认，有文件行号 | "run.cmd:97 用 start /min 拉起 magpie" | 可以 |
| **E3** | 推测、类比、经验，"看起来像" | "可能是浏览器标签页太多" | **不可以**——先补测 |

## 写法

- E1：`实测：整机 CPU 6%，内存 17/64GB（26%）。`
- E2：`代码确认：desktop/src/host.rs:74 用 CREATE_NO_WINDOW 拉起 run.cmd。`
- E3：`推测（未验证）：风扇声可能来自硬件积灰，本次未测硬件传感器，不下结论。`

## 铁律

- 没有采集脚本输出的数字，不许写 E1。
- 没有打开过源文件看到那一行，不许写 E2。
- E3 只能出现在"待排查"区，且必须说明缺什么证据。
- 报告里 E3 占比过高（>1/3）说明该继续测，不该硬凑结论。

## 与 tdd/验证纪律的关系
优化动作做完必须回归验证（重测增量、确认指标回落），否则"改了"不等于"好了"。验证不过不算完成。
