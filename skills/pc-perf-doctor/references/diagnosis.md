# 判据、常识与误判清单

> 只回答一个问题：拿到指标后，怎么判断"正常还是异常"。

## 一、内存：先看总量，再看占用率

Windows 会拿空闲内存做文件缓存（Standby/Modified），**"空闲少"不等于"不够用"**。

判据（本机实测基准，2026-11）：
- 总 63.7 GB / 空闲 46.7 GB / 提交 18 GB → **正常**。约 17 GB 占用在 64GB 机器上完全正常。
- 真正的内存压力信号：` committed / total > 0.85` 且 `free < 5%`，或"可用内存"持续低于 1GB 伴随卡顿。
- 单进程 WS 大 ≠ 泄漏。浏览器/WebView 用 3-4GB 是常态（多进程 + 渲染缓存）。

**"常态 20G"**：在 32GB 机器上偏高要查；在 64GB 机器上是正常水平。先问总量，别直接下结论。

## 二、CPU：唯一可信的是增量

任务管理器"CPU %"是该进程自启动以来的**平均值**归一化到单核，历史高会一直挂着，不代表现在在烧。

- `collect.py --delta PID 3` 返回 3 秒累计 CPU 时间差。
- 判据（N 核机器，`delta / 3` 为该进程占用的核心数）：
  - `delta / 秒 ≈ 1.0` → 占满一个核；风扇狂转的头号嫌疑。
  - `delta / 秒 ≈ 0` → 现在没在算，累计高只是历史。
  - `delta / 秒 > 2` → 多线程满载。
- 整机 CPU 用 `Win32_Processor.LoadPercentage`；整机低但单进程满核，说明是**单线程空转**（渲染循环、死循环、轮询），不是系统性负载。

## 三、常见误判（每条都踩过）

1. **看 WS 排序就说是它吃 CPU** → WS 是内存，不是 CPU。必须测增量。
2. **累计 CPU 233 秒 = 现在很忙** → 累计值。开机 8 小时平均每分钟不到 0.5 秒，可能现在根本没在算；也可能正在满核烧——只有增量能区分。
3. **内存占用 20G 不正常** → 看总量。64GB 用 20G 是 31%，正常。
4. **进程数 300=太多** → Windows 后台服务 + 现代应用多进程，300 可接受；400+ 且持续涨才查。
5. **风扇响就要重启/杀进程** → 先定位增量元凶，再动。很多时候是某个 WebView 渲染循环，针对性处理比重启精准。
