# classical-lens 沉淀

> 记录设计取舍与已知失效。每条都带理由，防止后续反复折腾同一件事。

## 一、设计取舍（为什么这样，不那样）

| # | 取舍 | 理由 | 撤销条件 |
|---|---|---|---|
| D1 | **39 套体系拆成两张 references，而非每套一个文件** | 每套一个文件会得到 39 个孤儿文件，路由表变成电话簿；且用户几乎总是一次看 3-5 副镜，分文件反而要多次读取。两篇（中/西）各 20-30KB，一次可加载 | 单篇超 60KB 或需按体系独立版本控制时拆分 |
| D2 | **不内置任何原文长段，只引精确篇目 + 短引** | 长段原文会占用大量上下文却无分析价值；且长引易错。短引 + 篇目让用户可自行核验 | 无 |
| D3 | **强制"真冲突"，不允许万镜归一** | 这是本技能与"多元视角"式空话的唯一分界。若所有镜都同意，说明选镜失败或不敢判断。已列为硬纪律 2 与一票否决前置 | 无（这是核心价值） |
| D4 | **强制"交叉盲区"一节** | 防止"多镜=周全"的错觉。所有透镜都照不到的地方，恰恰是最需要指出来的 | 无 |
| D5 | **分类用"首要追问"七类，不用朝代/国别/学派** | 朝代国别是出身不是用处；用户拿问题来需要"哪副镜照得出这个"。按追问分类，问题与透镜直接对接，一次跳转。跨时代同类（韩非与马基雅维利相隔 1800 年同属 Z）按国别分永远碰不到 | 无 |
| D6 | **"若只取一副"作为固定一节** | 强制分析者在多镜之后仍要收敛到一个可执行选择，并交代代价。避免"分析很全面但不知该做什么" | 无 |
| D7 | **内化定义为"八槽齐 + 过范畴关 + 先认盲区"，不是"通读经典"** | 39 套全读进上下文会淹没判断。八槽中"方法"槽是唯一能把思想转成操作的槽，"盲区"槽是唯一能防滥用的槽，二者最常被跳过，故单列 | 无 |
| D8 | **范畴混淆陷阱写 14 条具体清单，不写"注意语境差异"** | 抽象提醒无效；具体清单可逐条核。跨传统输出要求写核对行 | 出现新的高频误译时增补 |
| D9 | **佛学/禅宗/阿奎那仅作分析方法，不做信仰判定** | 避免技能被当作宗教权威；也避免"禅宗说"变成不可反驳的断言 | 无 |
| D10 | **易传/阴阳家明确禁止占筮** | 占卜不可验证且可能造成实际损害；但"时/位/应"的结构分析有独立价值，保留 | 无 |

## 二、已评估但不做（防反复折腾）

| # | 不做的 | 理由 | 撤销条件 |
|---|---|---|---|
| N1 | **不内置道德经/论语等全文** | 会过期于版本选择、占用上下文、且诱导"检索原文"而非"用方法" | 无 |
| N2 | **不做跨体系"综合评分"**（如给每副镜打分排序） | 评分需要一个共同尺度，而各体系的价值不可通约——这正是本技能要防的范畴错误。打分本身就会犯它要防的错 | 无 |
| N3 | **不提供"最佳视角"推荐** | 视角的适用性依赖问题的具体前提；给"最佳"等于跳过前提判断 | 无 |
| N4 | **不收录印度（吠檀多/数论）、日本（京都学派）等** | 用户明确要求"中西方都要有"，未要求其他；增加体系会稀释每副镜的深度。留待有真实需求时按 D1 的撤销条件扩展 | 用户明确要求，或出现必须用这些体系才能处理的问题类型 |
| N5 | **不做交互式问答来澄清问题类型** | 多数情况下可按"用户真正要什么"直接判定并在第〇段声明歧义与备选镜组；追问会打断交付 | 问题确实完全无法判类时（如"随便说说人生"）可追问一次 |
| N6 | **不写 README**（遵循 creat-skill references/07 第四节） | 技能目录内每多一个文件就多一份要维护的定义；入口是 SKILL.md | 若该目录同时作为独立 GitHub 仓库根目录发布，则需 README 面向访问者（参见 law-application 的同类偏离记录） |

## 三、已知失效（尚未修，诚实登记）

| # | 失效 | 影响 | 可能修法 |
|---|---|---|---|
| F1 | **体系覆盖面仍偏"哲学史主流"**，对民间智慧、兵法以外的实用传统（如《鬼谷子》《素书》、农书、医书中的方法论）未收 | 用户问"纵横家怎么看"时无镜可用 | 按需增补，走 D1 的拆分条件 |
| F2 | **"共同盲区"的识别依赖分析者的判断力**，无法机检 | 可能写成单镜盲区的复述 | 暂无自动化方法；在 rubric 第 4 项明确要求"该盲区不等于任何单镜的盲区" |
| F3 | **深潜模式的"可推翻条件"有时难以给出**（如庄子式问题本身是框架问题，可推翻条件模糊） | 可能写成套话 | 允许写"本判断的可推翻条件是：若你承认 X 前提，则整个框架失效" |
| F4 | **判类有时两可**（如"该不该辞职"既像 R 也像 C） | 选镜可能偏 | 已在 `references/04` 第五节给判定规则 + 第〇段要求声明歧义 |
| F5 | **evals 8 条 output 为自撰参考答案**，属 E5 自评 | 只能证明规范自洽，不能证明真实质量 | 需真实使用后补 E1/E2/E3 信号 |
