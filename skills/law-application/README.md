# law-application — 法条适用分析技能

一个端到端的法律适用分析技能（AI skill / prompt 包）。用户提交具体事件、案件材料或法律问题，它按固定方法论走完 **事实裁剪 → 程序前置 → 定性 → 规范与案例检索 → 涵摄 → 法律解释 → 冲突裁决 → 抗辩检视 → 证据发现 → 后果量化 → 兜底适用**，产出结构化的分析报告。

> ⚠️ **本技能输出的是结构化法律分析草稿，不构成法律意见，不替代执业律师。**
> 所有法条、案例、解释结论均须经官方法律数据库复核。涉及重大财产、人身自由或复杂程序事项，必须咨询执业法律专业人员。

## 为什么它和"问 AI 一个法律问题"不一样

| 普通 AI 回答 | 本技能 |
|---|---|
| 直接给结论 | 先做程序性前置（管辖/时效/前置程序），不通过就不做实体分析 |
| 凭记忆写"《民法典》第 X 条" | **条号纪律**：未经官方源核实一律写 `第〔待校验〕条`，禁止编造条号 |
| 不声明信息可靠度 | 报告第 0 节强制声明检索层级（MCP / 官方源 / 模型知识）与未核实条目数 |
| 结论看起来很有把握 | 置信度必须按判定表给依据，不凭感觉标"高" |
| 赔偿给一个精确数 | 给区间 + 数据来源 + 假设条件 |
| 到处都说"建议咨询律师" | 分析必须做完，免责声明只是附加项 |

## 三条硬纪律

1. **条号纪律** — 条文号未经官方源核实，写 `第〔待校验〕条`，绝不凭记忆写具体条号。
2. **程序前置** — 实体分析之前必答管辖、时效、前置程序三项；不答不做实体。
3. **降级声明** — 报告第 0 节写明本次检索用了哪一层、有多少条未核实。

## 流程（12 段）

| 段 | 做什么 | QC |
|---|---|---|
| S1 | 事实裁剪（九类事实 + 属性净化 + 约定/条款） | QC1 |
| S2 | 程序性前置（管辖 / 时效 / 前置程序） | QC2 |
| S3 | 法律关系定性（四域 + 行政行为三要件 + 竞合） | QC3 |
| S4 | 规范检索（四要素 + 效力状态 + 条号纪律） | QC4 |
| S5 | 案例检索（案号 + 层级 + 相似度） | QC5 |
| S6 | 涵摄（P-F-C + 中项 + 四谬误自检） | QC6 |
| S7 | 法律解释（文义→体系→目的→历史） | QC7 |
| S8 | 冲突裁决（位阶→特别→新旧→溯及力） | QC8 |
| S9 | 抗辩与效力检视（三分法） | QC9 |
| S10 | 证据发现与评估（C→E 映射 + 三性） | QC10 |
| S11 | 后果量化（区间 + 数据来源） | QC11 |
| S12 | 兜底适用（穷尽证明 + 红线） | QC12 |

QCn 恒定对应 Sn，判定表在对应 references 中。**"本阶段无需…"必须给理由**。

## 何时用 / 何时不用

**用**：用户提交事件经过或案件材料要做定性；问某事在法律上能否成立、构成什么；要算赔偿或量刑区间；要分析行政行为合法性；要判断某条法条是否适用。

**不用**：只要起草文书（起诉状/合同/答辩状）；只要查某条法条原文（直接检索更快）；已有一审判决只要写上诉理由；商业决策与合规咨询。

## 设计取舍（为什么这样设计）

| 决定 | 理由 |
|---|---|
| **不内置任何具体条文号** | 条文号会修正、会废止、地区差异大。内置必然在某天变成错误引用源，与条号纪律直接冲突 |
| **不内置赔偿标准数值** | 年度数据，必须现查当地统计局公报 |
| **不内置判例** | 会诱导模型套用而非检索，且判例效力层级复杂 |
| **12 段不压缩到 7 段以内** | 法律适用有法定顺序（定性前不能检索、涵摄前不能抗辩），合并会破坏方法论因果链。靠 references 分层控制单次加载量 |
| **把程序性前置独立成段** | 时效与管辖是法院可依职权审查的事项，不是"对方提了才查"。放在抗辩里等于把主动权交给对方，实务中是败诉主因 |

## 使用方式

**作为 AI 技能**：把本目录放入宿主技能目录（如 `skills/tool/law-application/`），宿主会按 `SKILL.md` 的 `description` 自动触发。

**作为人工检查清单**：直接读 `references/06-报告结构与反例.md` 的 14 条反例 + `SKILL.md` 的 10 条验收标准，逐条对现有分析打勾。
