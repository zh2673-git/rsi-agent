# 评分规则

## 一、两类判据

| 类型 | 判据 | 谁来判 |
|---|---|---|
| 硬门禁（可机检） | 条号纪律、程序前置已作答、检索层级已声明、四要素齐全、案例带案号 | assert（字符串检查） |
| 质量判据（需人判） | 三段论形式有效、要件三格归位、证据渠道可执行、量化区间合理、置信度有依据 | judge / human |

**硬门禁通过 ≠ 合格**。硬门禁只保证"没有明显编造"，不保证"分析正确"。

## 二、评分项（满分 20，建议 ≥14 才可交付）

| # | 项 | 分 | 判定 |
|---|---|---|---|
| 1 | 程序前置完整（管辖+时效+前置程序，含起算点计算） | 3 | 三项齐全且有时效计算过程 = 3；只写"未过时效"无计算 = 1；缺项 = 0 |
| 2 | 条号纪律（无凭记忆条文号） | 3 | 零违规 = 3；有 1 处未标注 = 1；有编造条号 = 0（直接不合格） |
| 3 | 事实净化（主观判断/法律评价已还原） | 2 | 全部净化 = 2；残留 1～2 处 = 1 |
| 4 | 定性准确（含行政行为三要件、竞合识别） | 2 | 主领域正确且竞合已标 = 2 |
| 5 | 涵摄形式有效（四谬误自检、中项明确） | 3 | 可独立复核 = 3；中项缺失 = 1；推不出却下结论 = 0 |
| 6 | 要件三格归位（无"基本满足"） | 2 | 全部归位 = 2；有模糊表述 = 0 |
| 7 | 证据渠道可执行 | 2 | 每条有主体/渠道 = 2；只列材料 = 0 |
| 8 | 量化有区间与来源 | 2 | 区间+来源+假设 = 2；单点精确数 = 0 |
| 9 | 置信度有依据 | 1 | 与置信度表对应 = 1；凭空标 = 0 |

## 三、一票否决项（任一出现即 0 分，不看总分）

- 凭记忆写条文号且未标 `[待校验]`
- 把已废止法规当现行法引用
- 刑法做不利类推
- 未做时效/管辖即下实体结论
- 用免责声明替代实质分析

## 四、案例来源

`cases.jsonl` 的 `source` 字段记录案例来自哪类真实场景。**不使用"模型认为"作为来源**（`run_evals` 会拒收）。

## 五、诚实声明（重要）

当前 `evals/cases.jsonl` 中 8 条案例的 `output` 字段为**技能作者按本技能规范撰写的参考答案**，属 E5 级自评信号，只能验证"规范是否自洽、是否可执行"，**不能证明真实用户场景下的分析质量**。

因此：
- `skill.json` 的 `verification` 为 `unverified`，不是 `verified`；
- 晋升到 `active` 需要至少一条 E1（用户确认）/ E2（测试通过）/ E3（真实结果）外部信号；
- 使用前建议先用真实案件试跑，把结果写回 `evals/results/` 并核对评分项。
