# 失败沉淀与内容评估

> 本文件两部分：一、对**原始 prompt** 的实质内容评估（发现的问题 + 修正）；二、本技能自身使用中积累的失败-修正对。

## 第一部分：原 prompt 内容评估（2026-11-13）

原 prompt 是一份单文件方法论（约 700 行），框架完整、术语准确、8 个原子方法 + 12 个原子技能划分合理。以下为逐项审计结果。

### A. 实质缺陷（已修正，影响结论正确性）

| # | 问题 | 位置 | 为什么是问题 | 本技能的处理 |
|---|---|---|---|---|
| A1 | **程序性前置缺失**：管辖、时效/期间、前置程序（行政复议/劳动仲裁）全流程无独立位置 | 编排链 S1→S9 全程无此项；时效只出现在 `defense-and-validity-review` 的抗辩类型里 | 时效与管辖是法院**可依职权审查**的事项，不是"对方提了才查"。放在抗辩里等于把主动权交给对方，实务中是败诉主因 | 新增 S2「程序性前置」段，独立于实体分析；任一不通过即终止实体分析（references/01 第四节） |
| A2 | **条号纪律缺失**：只要求"标注来源、检索时间、效力状态"，未禁止凭记忆写条文号 | 第三部分各原子技能的验证规则 | 模型最危险的失败模式不是"没标来源"，而是**编一个看起来对的条号**。用户会直接拿去用 | 立为第一硬门禁：未核实一律写 `第〔待校验〕条`，禁止"先写条号再笼统说以官方为准"（references/02 第三节） |
| A3 | **引用格式自相矛盾**：`失败模式` 里写"转由本技能第十节检索降级策略处理"，但检索降级在第十节、原子技能在第三部分，编号体系混用 | `norm-retrieval` / `case-retrieval` 的失败模式表 | 交叉引用指向不明，执行时找不到 | 全部改为显式文件名引用（references/02 等），不用"第十节"这类易错编号 |
| A4 | **置信度无判定标准**：报告模板要求写"置信度：高/中/低"，但全文未给判定依据 | 第二部分报告模板「综合结论」 | 无标准的置信度等于随机标注，反而制造虚假可信感 | 给出三档判定条件表（references/06 第二节），并要求置信度与 `[待校验]` 数量挂钩 |
| A5 | **民事赔偿公式口径过期风险**：写"残疾赔偿金＝受诉法院地上一年度**人均收入**×伤残系数×赔偿年限" | 原子技能 11 | "人均收入"表述模糊（城镇居民人均可支配收入 / 农村居民人均纯收入 / 全体居民人均可支配收入口径不同），且城乡二元标准已统一按城镇计 | 改为"城镇居民人均可支配收入"并强制标注**须查当地统计局最新公报**，不凭记忆给数值（references/05 第五节） |
| A6 | **刑事部分层次混用风险**：只提"罪名检索、量刑计算"，未规定犯罪论体系 | 场景路由「刑事案件」 | 中国刑法实务用三阶层（或四要件），两套混着说会导致违法性与有责性判断错位 | 明确写三阶层且顺序不可倒（references/07 第一节） |
| A7 | **"无法量化"处理太弱**：只说"输出本阶段无法量化，仅作定性分析" | 编排器 S8 | 没告诉用户**缺什么数据才能量化**，用户拿不到行动指引 | 改为必须列明缺失数据项 + 假设条件下的区间（references/05 第五节） |

### B. 结构问题（已重构）

| # | 问题 | 处理 |
|---|---|---|
| B1 | 单文件 700 行，8 框架 + 12 原子技能 + 编排器 + 模板全塞一处，超出 SKILL.md 篇幅预算，且 8 与 12 两套编号并行易混 | 拆为 SKILL.md（编排，≤150 行）+ 7 篇 references（每篇回答一个问题）。**合并 8 框架与 12 原子技能为单一 12 段主链 S1–S12**——原 prompt 的 8 框架与 12 原子技能有大量重叠（事实裁剪、定性、检索、涵摄、冲突、解释、抗辩、兜底 8 项两边都有），两套并行是同一件事的两种切法 |
| B2 | 场景路由 A/B/C/D/E 与标准调用链 S1→S9 并存，两套路径关系不明 | 只保留一条主链（S1→S12），场景差异改为"领域路由表"（SKILL.md 场景路由 + references/07） |
| B3 | 缺可填模板 | 新增 `templates/report-skeleton.md`（14 节可直接填）与 `templates/retrieval-ledger.md`（条号纪律的落地载体） |
| B4 | 缺可机检验收 | 原 prompt 验证规则全是自然语言（"是否明确""是否完整"），无法机检。改为 10 条验收判据，其中 6 条可机检（见 SKILL.md 验收段） |

### C. 原 prompt 做对了、予以保留的

| 项 | 评价 |
|---|---|
| 8 个原子方法的顺序（裁剪→定性→检索→涵摄→冲突→解释→抗辩→兜底） | 正确，符合法律适用方法论通说，予以保留为 9 段主链的骨架 |
| 三层检索降级（MCP → 联网 → 内部知识） | 正确且实用，强化为强制声明（报告第 0 节） |
| 民事请求权九阶检视 | 正确，是德式请求权基础的通行列举，保留并加"不得只走侵权"的打回信号 |
| 行政行为三要件（主体/权力/外部性） | 正确，保留为定性段的必检项 |
| 冲突裁决四规则（位阶/特别/新旧/溯及力） | 正确，但补了**适用顺序**（原 prompt 平列四规则，未说谁先谁后，会导致用特别法规则裁不同位阶冲突） |
| 事实属性四分法（客观/主观判断/法律评价/背景） | 正确且好用，保留 |
| 证据反例黑名单（6 条） | 正确，保留并补 2 条 |
| 免责声明与 `[待校验]` 标注意识 | 方向正确，但原 prompt 只把 `[待校验]` 用于"模型内部知识"，未扩展到"所有未核实条号"——已扩展 |

### D. 未修但需知的边界

| 项 | 说明 |
|---|---|
| 具体条文号 | 本技能**故意不内置任何条文号**。理由：条文号会过期、会修正、地区差异大；内置条号必然在某天变成错误引用。一律走检索 + 核实纪律 |
| 赔偿标准数值 | 同理不内置。地区年度标准必须现查 |
| 案例 | 不内置判例。内置判例会诱导模型套用而非检索 |

| # | 问题 | 根因 | 改法 |

| R2 | QC 编号与所在段系统性错位一格，且 QC9 有引用无定义 | QC 编号沿用了旧稿，段数调整后未重编 | 立"QCn 恒定对应 Sn"规则 + 在 SKILL.md 加 QC 定义位置索引表；各 references 的 QC 表全部重编为 QC1–QC12 |
| R3 | QC8 两套互斥定义（一处判证据、一处判兜底） | 同上，编号冲突未发现 | S10 证据归 QC10，S12 兜底归 QC12 |
| R4 | S1 与 S2 循环依赖：QC1 要求"P1/P2/P3 已作答"，但那是 S2 的内容 | 把"信息齐备"与"结论作答"混在一个检查点 | QC1 只查事实是否齐备；P1–P3 结论由 QC2 判 |
| R5 | 时效归属两处相反（一处说已移到 S2，一处仍要求抗辩段查） | 改进时只改了新增段，未回改旧段 | 立唯一归属：计算在 S2/P2，抗辩主张在 S9（只判是否主张、是否放弃）；references/05、06 同步改 |
| R6 | P2 打回信号要求在"事实裁剪"章节找计算，但 P2 属第 2 节 | 报告骨架改版后未同步打回信号 | 改为"第 2 节 P2 行无计算，或第 3 节时间格无变动节点 → P2 未做" |

| # | 缺口 | 补法 |

### 评审发现但**已评估不做**的（防止反复折腾）

| 项 | 为什么不做 |
|---|---|
| 内置具体条文号 | 条文号会修正、会废止、地区差异大。内置必然在某天变成错误引用源，与条号纪律直接冲突 |
| 内置赔偿标准数值 | 年度数据，必须现查当地统计局公报 |
| 内置判例 | 会诱导模型套用而非检索，且判例效力层级复杂 |
| 把 12 段压缩到 7 段以内 | creat-skill 第 4 步建议"单元 > 7 必须合并"，但法律适用有法定顺序（定性前不能检索、涵摄前不能抗辩），合并会破坏方法论的因果链。折中：段数保留 12，靠 references 分层控制单次加载量 |
| 技能目录内放 README.md（偏离 references/07 第五节"不写 README"） | 本技能同时是**独立 GitHub 仓库的根目录**，需要一个面向访问者的入口说明（三条硬纪律、结构、验证状态、设计取舍）。该文件不参与技能加载（宿主只读 SKILL.md + frontmatter），且已确认 `skill_validate --mode full` 不因其报错。若日后本技能回迁为 rsi-agent 内嵌技能、不再需要仓库入口，应删除本文件 |
