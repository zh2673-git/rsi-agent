# 02 规范与案例检索（含降级链）

> 解决的问题：法条从哪来、怎么判断它还有效、检索不到时怎么办。**这一篇是全技能最容易出错的地方**——法条编错、版本过期、把已废止的当现行，是法律类 AI 输出的头号事故。

## 一、三层降级链（不可跳级声明）

| 层级 | 方式 | 输出要求 |
|---|---|---|
| L1 | 已配置的法律 MCP（北大法宝 / 秘塔 / 其他法规库） | 标注库名 + 检索时间 + 链接或库内 ID |
| L2 | 联网检索官方源（国家法律法规数据库 flk.npc.gov.cn、最高法/最高检官网、人民法院案例库） | 标注 URL + 检索时间 |
| L3 | 模型内部知识 | **全部条目强制标 `[待校验]`**，且不得作为唯一依据 |

**降级必须显式声明**：报告须写明"本次检索使用 L2，L1 未配置"。未声明即视为 L3 冒充 L1，属交付不合格。

## 二、法条四要素（缺一不可）

每条被引用的规范必须同时给出：

```
名称 + 条文号 + 现行有效版本 + 效力状态
```

| 要素 | 反例（不合格） | 正例 |
|---|---|---|
| 名称 | "合同法规定" | 《中华人民共和国民法典》 |
| 条文号 | "民法典关于违约的规定" | 第 X 条（第 X 款第 X 项） |
| 版本 | "民法典" | 2020-05-28 通过，2021-01-01 施行 |
| 效力状态 | 无 | `VALID` / `AMENDED` / `REPEALED` / `UNCERTAIN` |

**效力状态取值**：

| 状态 | 含义 | 处理 |
|---|---|---|
| `VALID` | 现行有效 | 可直接引用 |
| `AMENDED` | 已修正，须引现行版本 | 引用修正后条文，并注明修正年份 |
| `REPEALED` | 已废止 | **禁止作为现行法引用**；仅可作历史沿革说明 |
| `UNCERTAIN` | 无法确认 | 标 `[效力存疑]`，降低置信度，不得单独支撑结论 |

## 三、条号纪律（本技能的第一硬门禁）

**条文号未经官方源核实，一律不得直接书写。**

允许的两种写法：

1. 已核实 → 正常书写条文号，并在来源栏给出 URL/库 ID；
2. 未核实 → 写 `《法律名称》第〔待校验〕条`，内容描述放在括号内。

**禁止**：凭记忆写"第 X 条"再在末尾笼统加一句"以官方为准"。这类输出会让用户直接拿去用，是最危险的失败模式。

> 判断标准：把这句话交给一个律师，他能不能直接据以翻到原文？不能 → 不合格。

## 四、正式法源层级与检索顺位

| 位阶 | 制定机关 |
|---|---|
| 宪法 | 全国人大 |
| 法律 | 全国人大及其常委会 |
| 行政法规 | 国务院 |
| 地方性法规 | 省级/设区的市人大及其常委会 |
| 部门规章 | 国务院各部委 |
| 地方政府规章 | 省级/设区的市政府 |
| 司法解释 | 最高法/最高检 |

**领域检索顺位**：

| 领域 | 顺位 |
|---|---|
| 民事 | 合同 → 类契约（悬赏/缔约过失）→ 无因管理 → 物权 → 不当得利 → 侵权 |
| 刑事 | 分则罪名 → 总则（未遂/共犯/责任年龄）→ 单行刑法 → 司法解释 |
| 行政 | 法律 → 行政法规 → 地方性法规 → 规章 → 司法解释 → **行政规范性文件（条件触发）** |
| 宪法基本权利 | 宪法 → 法律 → 比例原则与法律保留审查 |

### 民事请求权九阶检视

①合同 ②单方法律行为 ③类契约 ④身份法 ⑤无因管理 ⑥物权 ⑦占有保护 ⑧不当得利 ⑨侵权

**打回信号**：民事案件报告只分析侵权，未说明为何前八阶不成立 → QC3 不通过。

### 行政规范性文件触发条件

| 情形 | 自动检索 |
|---|---|
| 行政行为三要件满足 | ✅ |
| 行政机关作为民事主体 | ❌ |
| 民事/刑事/宪法案件 | ❌（可按需提示） |
| 领域不明或行民交叉 | ⚠️ 提示用户 |

## 五、案例检索

| 层级 | 效力 | 来源 |
|---|---|---|
| 指导性案例 | **应当参照** | 最高法发布 |
| 公报案例 | 重要参考 | 《最高人民法院公报》 |
| 参考性案例 | 参考 | 高院发布 |
| 一般裁判 | 参考 | 裁判文书 |

**每条案例必须给**：案号 + 法院 + 来源 + 检索时间 + 相似度（高/中/低 + 理由）。
内部知识案例标 `[待检索]`。

**打回信号**：只有"类似案例显示法院通常支持"而无案号 → 未完成检索。

## 六、交叉验证

优先用至少两个独立来源交叉验证同一法条。两个来源冲突时：

1. 以官方数据库（flk.npc.gov.cn）为准；
2. 若官方库也无该条 → 标 `[效力存疑]`，不引用；
3. 记录冲突本身进报告（这是有价值的信息，说明该规范存在版本混乱）。

## 七、S4–S5 判定表（QC4 / QC5）

| 检查点 | 段 | 检查项 | 通过标准 | 失败动作 |
|---|---|---|---|---|
| QC4 | S4 | 覆盖焦点 | 每个争议焦点都有候选规范 | 回退 QC3 |
| QC4 | S4 | 四要素完整 | 名称/条号/版本/效力状态齐全 | 补齐后再继续 |
| QC4 | S4 | 条号已核实 | 无"凭记忆写的条文号" | 改为 `第〔待校验〕条` |
| QC4 | S4 | 降级已声明 | 写明本次使用的检索层级 | 补声明 |
| QC4 | S4 | 顺位正确 | 按领域顺位从高位阶检索 | 重检索 |
| QC4 | S4 | 请求权无遗漏 | 民事已走完九阶 | 补检视（归 QC3） |
| QC5 | S5 | 案例带案号 | 每个案例有案号+法院+来源 | 补检索或删引用 |
| QC5 | S5 | 层级区分 | 已区分指导性/公报/参考性/一般 | 补标注 |
| QC5 | S5 | 相似度理由 | 标"高"须给至少 3 个匹配维度 | 补理由或降级 |
| QC5 | S5 | 无类案已声明 | 写「未发现典型类案」+ 已尝试的检索条件 | 补声明 |

## 八、失败模式

| 场景 | 动作 |
|---|---|
| 检索完全不可用 | 走 L3，全标 `[待校验]`，报告开头显著声明"法条未核实" |
| 无法确认效力 | 标 `[效力存疑]`，降置信度 |
| 地方性规定需要但无地域信息 | 停下来问用户地域（不能猜） |
| 找到的法条与用户描述的事实对不上 | 不强行套用；标注"要件不匹配"，考虑相近规范 |
| 发现引用的法条已废止 | 明确写出废止时间与替代规范，**不要静默替换** |
