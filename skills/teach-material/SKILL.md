# 课件生产（不是把文档改个标题）

一份材料能叫「课件」，靠的不是排版，是这四件事都可判：

| 件 | 不可判的反面 | 可判的正面 |
|---|---|---|
| 学习目标 | 「理解 X」 | 「能回答：X 与 Y 的区别是什么」 |
| 概念顺序 | 按作者想到的顺序 | 按前置依赖拓扑序（无环） |
| 练习 | 几道泛泛的思考题 | 每题挂到某个目标 + 有参考答案 |
| 验收 | 「我觉得写清楚了」 | `check` 退出码 0 |

本技能把四件事落成 `scripts/lesson.py` 的 spec + 机检。

## 何时用

- 「把这份研究做成课件 / 讲义 / 教程 / 培训材料」
- 「这份材料能不能拿去教人」
- 不适用：写技术文档（那是 `deepseek-paper` / 直接写）、写 README

## 为什么是「产课件」而不是「当导师」

这两件事落点完全不同，别混：

| | 形态 | 本仓库适配度 |
|---|---|---|
| 甲：当导师 | 跨会话学习者模型、出题、判掌握、推下一步 | **低**——受益者只有一个人，投入全新建 |
| 乙：产课件 | 把已有结论变成有结构可验收的材料 | **高**——输入（`outputs/*.md`）与输出都在已有通道里 |

先做乙。等真有人按课件学、并要求「按我的水平调整」，再谈甲——那时才有数据支撑学习者模型该长什么样。

## 流程五步

### 1. 初始化，指向源材料

```
python scripts/lesson.py <主题> init --from outputs/<源文档>.md --intro "一句话说明这是给谁看的"
```

`--from` 不是装饰：课件里每条结论都应能追回源材料，否则它只是「另一份看法」。

### 2. 写可判的学习目标

```
python scripts/lesson.py <主题> goal add "能说清 A 通道与 B 通道的调用方不同" --check "B 通道由谁直接调用？"
```

`--check` 是**能回答的问题**。写不出检验问题，说明这个目标本来就不可判——那就别写进去。

### 3. 立概念与前置

```
python scripts/lesson.py <主题> concept add "embedding" 
python scripts/lesson.py <主题> concept add "RAG" --after "embedding" --body "正文..."
python scripts/lesson.py <主题> concept order     # 拓扑序；成环则报错
```

**成环必须改依赖，不能硬排**：教学材料里出现循环前置，读者读到哪一节都缺东西。
`order` 退出码 1 就是让你回去改，不是让你绕过。

### 4. 练习挂到目标

```
python scripts/lesson.py <主题> exercise add "题干" --answer "参考答案" --goal O1
```

挂不上目标的题是「有趣的旁支」，不是这门课的一部分。`check` 会把它们列出来。

### 5. 出稿 + 机检

```
python scripts/lesson.py <主题> build --out outputs/课件-<主题>.md
python scripts/lesson.py <主题> check outputs/课件-<主题>.md
```

## 验收（可机检）

| # | 判据 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 每个目标都有检验问题 | `check` | `errors` 里无「缺检验问题」 |
| 2 | 概念依赖无环 | `concept order` / `check` | 退出码 0，`cyclic` 为空 |
| 3 | 每道题挂到有效目标 | `check` | `errors` 里无「未挂到有效目标」 |
| 4 | 每道题有参考答案 | `check` | `errors` 里无「缺参考答案」 |
| 5 | 目标全覆盖 | `check` | `warnings` 里无「目标无对应练习」 |
| 6 | 正文含全部目标 | `check` | `errors` 里无「正文缺目标」 |
| 7 | 总判 | `check` | 退出码 0 |

`warnings` 允许存在（比如某个概念暂时没正文），但 `errors` 必须清空才算出稿。

## 正课正文怎么写

`--body` 里写什么，决定课件是「目录」还是「材料」：

- **一概念一断言**：每个概念至少给一句「它解决什么问题」，而不是「它是什么」。
- **给反例**：能说出「什么情况下不该用它」的人才是真懂。
- **留可追的出处**：源材料里的章节/文件名写上，别让读者去猜。
- **不写「综上所述」**：那种句子在课件里没有信息量。

## 反面清单

- **不要**把源文档整段搬进来当正文：那是复制，不是教学——源文档的组织顺序是「作者想说的」，
  课件要的是「读者该按什么顺序接收」。
- **不要**为了凑满每个目标而造题：`check` 的 `warnings` 允许「目标无练习」，但一道硬凑的题比没有更糟。
- **不要**在环上绕：`concept order` 报环就回去改依赖，别把 A 的前置删掉只为过检查——那会让读者在 A 那节真的看不懂。
- **不要**把 `.rsi/lessons/` 当产物：spec 是工作文件，交付物落 `outputs/`。
