# 失败-修正库

> 最高价值的沉淀。格式固定：**现象 → 根因 → 改法 → 是否生效**。
> 同一改法出现 3 次，升为规则；规则被推翻，降为「已评估不做」。

## FF-001 步骤空壳

| 项 | 内容 |
|---|---|
| 现象 | 技能有完整目录和步骤，但不看理论就不知道该怎么判 |
| 根因 | 只做了任务分解，没做质量责任划分 |
| 改法 | 每个单元必须有判据 + 失败信号；删掉理论段后仍能判断才算合格 |
| 是否生效 | 待补 |

## FF-002 理论装饰

| 项 | 内容 |
|---|---|
| 现象 | 每个单元都挂了学科理论，但推不出任何具体规则 |
| 根因 | 把"引用"当"深度" |
| 改法 | 三段式检验：理论 → 规则 → 校验信号，断在哪删到哪 |
| 是否生效 | 待补 |

## FF-003 固定算子

| 项 | 内容 |
|---|---|
| 现象 | 所有工作都用同一套切法（如四层或部门制） |
| 根因 | 把某一领域的形状当成万能公式 |
| 改法 | 先问"这类工作最怕什么"，再在流水线/角色制/递归/决策树/状态机里选 |
| 是否生效 | 待补 |

## FF-004 验收缺失

| 项 | 内容 |
|---|---|
| 现象 | 技能自称"已验证"，实际只有模型自评 |
| 根因 | 没有外部信号，也不愿承认 |
| 改法 | 三级验收；缺第三级必须标「未验证」 |
| 是否生效 | 待补 |

## FF-005 过度工程

| 项 | 内容 |
|---|---|
| 现象 | 为对称凑文件、角色多到记不住谁拍板、模板比正文长 |
| 根因 | 照搬行业的人力分工，没做 AI 裁剪 |
| 改法 | 按失败模式合并角色；定档位；执行复杂度预算 |
| 是否生效 | 待补 |

## FF-006 和下游抢主导权

| 项 | 内容 |
|---|---|
| 现象 | 两个技能都想管同一步，流程互相打架 |
| 根因 | 契约里没写边界 |
| 改法 | 固定写「不做什么 / 下游是谁、交什么工件」 |
| 是否生效 | 待补 |

## FF-007 和内置 skill-creator 抢活

| 项 | 内容 |
|---|---|
| 现象 | 又把目录规范、frontmatter 写法写了一遍 |
| 根因 | 边界不清 |
| 改法 | 封装交给 skill-creator，本技能只管内容方法论 |
| 是否生效 | 待补 |

## FF-008 沉淀自我强化

| 项 | 内容 |
|---|---|
| 现象 | 沉淀库越积越多，但都是模型自己的偏好，没有真实反馈 |
| 根因 | 只记"经验"，不记"失败与修正" |
| 改法 | 以失败-修正对为主；标杆卡必须带失效边界与来源 |
| 是否生效 | 待补 |

## FF-009 优化无基线

| 项 | 内容 |
|---|---|
| 现象 | 改完自我感觉变好，但说不出哪里变好，也无法证明旧能力还在 |
| 根因 | 跳过基线，直接改；只测新问题，不测回归 |
| 改法 | 走 references/06：冻结基线 → 分层定位 → 单点改动 → 三类回归 → 保留/回退 |
| 是否生效 | 待补 |

## FF-010 跨层一起改

| 项 | 内容 |
|---|---|
| 现象 | 一次同时改本质、结构和措辞，出问题无法归因 |
| 根因 | 想一次改到位 |
| 改法 | 一次只动一层（L0–L4）；跨层按重构/新建处理 |
| 是否生效 | 待补 |

## FF-011 依赖宿主内置工具

| 项 | 内容 |
|---|---|
| 现象 | 技能写着"遵循内置 skill-creator"，换到没有该工具的 agent 上就无法封装 |
| 根因 | 把宿主能力当默认前提 |
| 改法 | 自带 references/07 最小封装规范；宿主有内置则兼容，没有也能独立跑 |
| 是否生效 | 待补 |
