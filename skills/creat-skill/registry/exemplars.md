# 标杆卡

> 用法：新建前先检索这里，能改造就不新建。
> 每张卡写清「适用条件 / 失效边界 / 为什么好 / 可借鉴的语法」。
> 提取语法，不提取成品。

## 卡 001 · make-video（视频编译）

| 项 | 内容 |
|---|---|
| 适用条件 | 把自然语言创意编译成程序化视频；需要稳定质量、可断点、可局部重试 |
| 还原来源 | 电影工业：部门制、前置制作、剪辑、"翻译损耗是第一危险" |
| 为什么好 | 把"惊艳"从运气变成配置：规范笼子 + 风格包 + 类型配方 |
| 可借鉴的语法 | 角色=专业容器（职责/理论/工件/校验/反例/标杆）；工件化交接；V-* 单一权威登记；风格沉淀五步（匹配优先→解剖→对拍→上架） |
| 失效边界 | 强绑定视频域；风格库会膨胀；模板化有过同质化风险 |
| 可迁移到 | 任何多专业协同、且有大量"换手"的内容生产流程 |

## 卡 002 · project-dev（项目方法论编排）

| 项 | 内容 |
|---|---|
| 适用条件 | 项目级工作：从零开发 / 逆向解读 / 存量优化 |
| 还原来源 | 软件工程方法论（时空运行时：空间 + 时间 + 规则） |
| 为什么好 | 先判模式再动手；本质先行 + 契约闸；递归四层可复用到任意粒度 |
| 可借鉴的语法 | 三分法模式判定；PLAN.md 迭代纪律；「已评估不做」；P/Q/I 验收 |
| 失效边界 | 把四层套到非软件工作会削足适履；对一次性小任务过重 |
| 可迁移到 | 任何需要"先判模式、再按粒度递归"的复杂工作 |
