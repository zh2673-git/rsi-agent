# 04 收敛与裁剪

> 解决的问题：还原出来的行业体系是给"人"设计的，直接照搬会多出一堆 AI 不需要的协调成本。
> 裁剪不是简化内容，是去掉**人力约束带来的结构**。

## 一、为什么要裁

| 行业里的约束 | AI 里是否成立 | 处理 |
|---|---|---|
| 人有专长边界 | 一个模型可扮多角色 | 角色可合并 |
| 有工时与排期 | 无 | 删掉排期类角色 |
| 有资质门槛 | 无 | 改成检查清单 |
| 有部门墙与审批 | 无 | 改成校验器 + 人工触点 |
| 经验靠年限积累 | 可靠反例库快速逼近 | 把"资历"改成"反例" |

## 二、裁剪五条

1. **按失败模式合并角色**：同错合并，不按职称合并。
2. **删纯协调角色**：不产出判断的，一律改成流程检查点。
3. **把"人审会"改成"校验器 + 人工触点"**：人能介入的地方要少而准，不要每步都停。
4. **把"资质门槛"改成"检查清单"**：能不能做，改成分项自检。
5. **把"经验年限"改成"反例库"**：资历不可复制，失败可复制。

## 三、先定档位

| 档位 | 适用 | 单元数 | 工件数 | references | 验收 |
|---|---|---|---|---|---|
| 轻量 | B 类、单次重复 | 3–5 | 1–2 | 0–1 | 自检 + 同行 |
| 标准 | A 类、长期重复 | 5–7 | 3–6 | 3–5 | 三级验收 |
| 深度 | C 类、新领域 | 由试跑定 | 2–3 起 | 按需 | 试跑驱动 |

档位写进契约。档位不对，后面全是白工：轻量档做成 20 个工件会没人用，深度档只写 3 步会不靠谱。

## 四、复杂度预算

- `SKILL.md` ≤ 150 行；超过说明编排层在写细节，下沉到 references；
- 单元 > 7 个必须合并或分层；
- 每篇 reference 只回答一个问题；回答两个就拆；
- 没有被 `SKILL.md` 引用的文件，删掉；
- 模板必须能直接填，不能是说明文；
- 角色数量不应超过"人能记住谁拍板"的程度。

## 五、过度工程的信号

| 信号 | 说明 | 改法 |
|---|---|---|
| 为了对称凑文件 | 每个部门都要一篇文档 | 按问题分篇，不按组织图分篇 |
| 每个单元都挂了理论 | 但说不出校验 | 删到只剩能推出规则的 |
| 角色多到记不住谁拍板 | 分工细化过头 | 合并 + 补裁决表 |
| 模板比正文还长 | 形式压过内容 | 模板只留必填项 |
| 没人消费的工件 | 生产了但下游不用 | 删掉 |

## 六、裁剪不能动的三样

裁剪只动结构，不动这三样：

1. **质量责任的划分**——可以合并角色，不能取消"谁负责"；
2. **验收标准**——可以简化形式，不能没有打回信号；
3. **反例**——可以归档，不能删。删了就会重复踩坑。

## 七、和下游的边界

技能必须写明「我不做什么，交给谁」。两个技能都想主导同一步，最后一定打架。

契约里固定两行：

```
不做什么：
下游是谁、交什么工件：
```

例：剧本技能不做画面与配音，交给 make-video，交接工件是带 `function/beat` 标注的讲稿。
