# 06 存量优化

> 解决的问题：把"改一改"变成可回退、可验证的闭环。
> 铁律：**没有基线，就没有优化，只有改动。**

## 一、闭环七步

```
冻结基线 → 定问题 → 分层定位 → 单点改动 → 回归验收 → 保留/回退 → 记录沉淀
```

任一步跳过，这次改动就只能叫"试试看"，不能叫优化。

## 二、冻结基线（最容易被跳过）

改之前先存档，否则改完无法判断好坏。

| 项 | 内容 |
|---|---|
| 输入 | 3–5 个历史任务；没有历史就用 3 个代表任务现场跑一遍 |
| 输出 | 结果文件 + 判据打分表 |
| 触发记录 | 哪些话术触发了、哪些该触发却没触发 |
| 版本 | 记下当前技能版本或 commit |

基线必须可对比：同一批输入、同一套判据、同样的记录粒度。

## 三、定问题

只写现象和证据，不写解决方案：

```
现象：用户说"帮我改一下这个视频"，技能没触发
证据：10 条真实话术里漏触发 4 条
影响面：所有优化类请求
```

「我觉得不够好」不是问题，「哪类输入、出了什么错、错了几次」才是。

## 四、分层定位：先确定改哪一层

| 层 | 症状 | 风险 | 典型动作 |
|---|---|---|---|
| L0 本质 | 做成了另一件事 | 最高，等于重写 | 回到契约第 1 节 |
| L1 结构 | 漏环节、单元重叠、算子选错 | 高 | 增删单元、换算子 |
| L2 规则 | 判得不准、冲突时飘 | 中 | 改判据、优先级、校验信号 |
| L3 工件 | 交接丢信息、不可校验 | 中 | 改字段、schema、补双轨 |
| L4 模板与措辞 | 触发不准、表达含糊、格式乱 | 低 | 改 description、示例、格式 |

**铁律：一次只动一层。** 跨层一起改，出问题无法归因，只能整体回退。

## 五、单点改动

- 一次只验证一个假设；
- 改之前先写「如果有效，应该看到什么」——没写预期的改动不许做；
- 不顺手重构，优化不是重写；
- 改 L0/L1 时停一下：这已经接近重写，按新建流程重走契约，别在原地硬掰。

## 六、回归验收（技能版的"不变量"）

三类全过才算成功：

| 类别 | 怎么测 | 不过怎么办 |
|---|---|---|
| 新问题 | 第 3 步的证据是否消失 | 无效 → 回退或换假设 |
| 旧能力 | 基线案例回放，结果不退化 | 回退：破坏了原有能力 |
| 触发兼容 | 列 10 条真实话术，该触发的触发、不该触发的不触发 | 修 description，不放宽凑数 |

触发测试必须覆盖四类话术：

1. 明确该触发；
2. 模糊、可能触发；
3. 明确不该触发；
4. 旧版能触发、新版可能漏掉。

第 4 类最容易漏，也最伤使用体验。

## 七、保留还是回退

| 结果 | 决策 |
|---|---|
| 三类全过 | 保留，写迭代记录，升版本 |
| 新问题解决、旧能力退化 | 默认回退；确有必要接受退化，必须写进 PLAN 并说明理由 |
| 都没解决 | 回退，记「已评估不做」，写清为什么 |

**禁止因为"改都改了"而保留。** 这是优化里最常见的自欺。

## 八、记录格式（PLAN 迭代记录）

```
## 迭代 N · 日期
问题：现象 + 证据
定位：L2 规则
改动：<一句话>
预期：<可观察指标>
回归：新问题 ✅/❌ · 旧能力 ✅/❌ · 触发 ✅/❌
决策：保留 / 回退
沉淀：FF-00X
```

沉淀走 05：现象 → 根因 → 改法 → 是否生效。

## 九、优化、重构还是新建

| 情况 | 选择 |
|---|---|
| 本质对、结构对，只是判据不准 | 优化（L2 / L3） |
| 结构漏环节或算子选错 | 重构（L1），按新建流程重走契约 |
| 本质就错了 | 新建；旧技能标废弃，不硬改 |
| 已有别的技能更接近 | 匹配优先，改造那个 |

## 十、闭环完成判据

- [ ] 有基线存档，且能对比
- [ ] 问题写成现象 + 证据，不是感受
- [ ] 改动只落在一层
- [ ] 改动前写过预期
- [ ] 三类回归全过
- [ ] 有保留或回退的决策与理由
- [ ] 有沉淀条目
- [ ] 验证状态是按 05 诚实标注的（没有外部信号就仍是「未验证」）
