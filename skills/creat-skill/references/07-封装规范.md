# 07 封装规范

> 解决的问题：不同 agent 未必内置 `skill-creator`。本技能自带一套**最小兼容集**，保证产物在常见宿主上都能被识别。
> 原则：内置可用则优先遵循宿主额外要求；没有内置，也能独立完成封装。冲突时以宿主为准。

## 一、最小可识别单元

一个技能 = **一个目录 + 一个 `SKILL.md`**。没有 `SKILL.md` 就不算技能。

- 目录名与 frontmatter 的 `name` 一致；
- 目录名用 kebab-case（小写字母、数字、连字符），不用空格、下划线、中文；
- 目录内可以有子目录，但不是必需。

## 二、frontmatter：只写必需的

```yaml
---
name: <kebab-case，与目录同名，常见上限 64 字符>
description: <做什么 + 什么时候触发，第三人称>
---
```

规则：

| 项 | 要求 | 常见错误 |
|---|---|---|
| name | 小写 + 连字符，与目录一致 | 用中文、空格、下划线 |
| description | 第三人称，含触发词 | "我可以帮你……" |
| 长度 | 建议 ≤500 字（常见上限约 1000 字符） | 写成一篇小作文 |
| 可选字段 | `license`、`allowed-tools`、`metadata` 等只在宿主支持时加 | 加了宿主不识别的字段 |

**不确定宿主支持哪些可选字段，就不加。** 少一个字段不会坏，多一个可能解析失败。

## 三、description 写法（最影响能不能被调用）

三段式：**做什么 → 什么时候用 → 边界（可选）**。

正例：

```
技能编译器：先还原一个行当的专业生产体系，再转译成 AI 可执行的 skill。
支持新建、逆向审计、存量优化与沉淀。
Invoke when 用户要"做一个技能/改造技能/审计技能"。
```

反例：

```
这是一个非常强大的技能，可以帮助你完成各种任务。
```

反例的问题：没有触发词，模型不知道什么时候该调用它。

**自检**：把 description 单独拿给一个不了解项目的人看，他能不能说出"什么情况下该用"。

## 四、正文结构

`SKILL.md` 只放四类内容：

1. 何时用 / 何时不用；
2. 模式与步骤（编排）；
3. 路由（去哪个文件读细节）；
4. 输出前自检。

其余全部下沉：

| 内容 | 放哪 |
|---|---|
| 理论、细则、话术 | `references/`，一篇只回答一个问题 |
| 可填工件 | `templates/` |
| 该技能自己的沉淀 | `registry/` |
| 需要执行的代码 | `scripts/`（可选） |
| 静态资源 | `assets/`（可选） |

**不写 README、CHANGELOG、INSTALL 之类的额外文档。** 技能目录里每多一个文件，就多一份要维护的定义。

## 五、渐进披露

| 层 | 何时加载 | 放什么 |
|---|---|---|
| 元数据 | 常驻，决定是否触发 | `name`、`description` |
| `SKILL.md` | 触发后 | 编排、步骤、路由 |
| `references/` | 按需 | 细节 |
| `templates/`、`registry/` | 用到时 | 工件与沉淀 |

因此：

- `SKILL.md` 越短，触发后占用越少；
- 细节必须有路由，不能"藏在某个文件里但没人知道"；
- 每个 reference 都要被 `SKILL.md` 引用，**孤儿文件删掉**。

## 六、篇幅预算

- 本技能自定：`SKILL.md` ≤ 150 行；
- 常见宿主建议：`SKILL.md` ≤ 500 行；
- 单元超过 7 个必须合并或分层；
- 模板必须能直接填，不能是说明文。

## 七、落盘位置

| 级别 | 位置 | 说明 |
|---|---|---|
| 项目级 | 宿主约定的项目技能目录（本环境为 `skills/tool/<name>/`；若宿主用 `.trae/skills/`，放那里） | 只对当前项目生效 |
| 全局级 | 宿主约定的用户技能目录 | 跨项目生效 |
| 不确定 | 跟随当前技能所在根目录，或直接问用户 | 不要猜 |

**同一技能只保留一份定义。** 同时存在项目级和全局级副本，行为会打架，且很难排查。

## 八、安装后自检

- [ ] 目录名 == `name`
- [ ] frontmatter 能被 YAML 解析，没有多余字段
- [ ] description 是第三人称，含真实触发词
- [ ] `SKILL.md` 引用的每个文件都存在
- [ ] 没有孤儿 reference、没有 README 之类多余文档
- [ ] `SKILL.md` 在篇幅预算内
- [ ] 用 3 条真实话术试触发：该触发的触发，不该触发的不触发
- [ ] 换一个人只读技能，能说出第一步该做什么

## 九、和宿主内置工具的关系

- 宿主已内置 `skill-creator`：先读它的额外要求，能兼容就兼容；
- 宿主没有内置：直接按本规范做，产物一样可用；
- 两者冲突：**以宿主为准**，但把差异记进 `registry/failure-fixes.md`，避免下次再踩。

本规范是**最小兼容集**，不是完整规范。它的目标只有一个：让技能在陌生 agent 上也能被正确发现和加载。
