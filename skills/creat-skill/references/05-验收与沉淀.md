# 05 验收与沉淀

> 解决的问题：技能写完不等于能用。没有外部信号，"验证"和"沉淀"都会变成模型自我强化。

## 一、三级验收

| 级 | 谁验 | 怎么验 | 能证明什么 |
|---|---|---|---|
| 1 自检 | 技能自己 | 跑 2–3 个历史案例回放，看判据能不能判出好坏 | 规则不自相矛盾 |
| 2 同行 | 另一个人 / 另一个 agent | 只读技能，做同一任务，比结果 | 技能是否可独立使用 |
| 3 外部信号 | 真实使用者 / 真实任务 | 真实场合的结果、盲评、A/B | 是否真的有效 |

**第三级是唯一的硬信号。** 缺它，就必须标「未验证」。

### 低成本的第三级替代

- **历史案例回放**：拿过去真实发生过、结果已知的案子跑一遍；
- **小样本试跑**：3 个样本，不求统计显著，只求暴露大坑；
- **盲评**：去掉来源标签，让不知情的人二选一；
- **失败复盘**：专门找已知失败案例，看技能能不能提前拦住。

## 二、验证状态三档

每个技能头部或 registry 必须写明：

| 状态 | 含义 | 允许的表述 |
|---|---|---|
| 已验证 | 有第三级信号 | 可以说"有效" |
| 部分验证 | 只有一、二级 | 只能说"结构完整、未见明显问题" |
| 未验证 | 只有设计推理 | 必须写"未验证" |

**禁止把「未验证」写成「已验证」。** 这是最容易发生、也最伤信任的失真。

## 三、沉淀四种

按价值从高到低：

### 1 失败-修正对（最高价值）

```
现象：第 5 集角色说话方式突然变了
根因：写新一集时没有回读系列圣经
改法：每集写前强制读 A0，写后跑连续性 diff
是否生效：第 6–8 集未再出现
```

比任何理论引用都值钱，因为它带真实反馈。

### 2 标杆卡

```
适用条件：同事午饭、3–5 人、气氛轻松
失效边界：有领导在场时不成立
为什么好：自嘲 + 共同经历，威胁低、共鸣高
可借鉴的语法：先自曝，再让听者代入
```

**提取语法，不提取成品。** 参考不是照抄。

### 3 配方

可组合的默认参数。例：`自嘲 + 共同经历 + 三法则` 是稳定组合。
配方要标适用档位，不要当成万能公式。

### 4 反例库

按单元归档。格式：现象 / 根因 / 对应规则 / 是否已修。

## 四、沉淀放哪里

| 位置 | 放什么 | 谁用 |
|---|---|---|
| 技能内 `registry/` | 该技能专属的反例、标杆、配方 | 本技能迭代 |
| 全局库 | 跨技能可复用的判断与反模式 | 所有技能 |

同一条经验只放一处，另一处引用。重复登记必然打架。

## 五、升级与降级

- 同一个修正出现 **3 次** → 升为规则；
- 规则被真实案例推翻 → 降为「已评估不做」，写明为什么，防止反复折腾；
- 标杆卡带来源与时间；过期的**标注**，不删除。

## 六、匹配优先

新建或新增沉淀前，固定走一遍：

```
检索已有技能与 registry
  → 有高度相似的？→ 改造 / override
  → 只是参数不同？→ 存为配方
  → 差异确实大？→ 新建
```

这条直接决定沉淀库会不会膨胀成一堆没人看的笔记。

## 七、交付前最后一遍

- [ ] 验证状态写了吗，是诚实的吗？
- [ ] 失败-修正对有没有至少一条？
- [ ] 标杆卡有没有写失效边界？
- [ ] 新沉淀有没有先检索、避免重复登记？
