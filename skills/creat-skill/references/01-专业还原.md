# 01 专业还原

> 解决的问题：怎么把"这行专业的人是怎么干活的"从模糊印象，变成一张可核对的谱系图。
> 前提命题：**专业分工的本质不是任务分配，是质量责任分配。** 所以还原的目标永远是回答「谁对什么质量负责」。

## 一、先判类型

| 类型 | 判断依据 | 还原对象 |
|---|---|---|
| A 成熟行业 | 有明确岗位、有交付物、有验收、有行规/标准/认证 | 角色谱系 + 工件链 + 校验标准 |
| B 高手实践 | 有公认的高手和作品，但没有形成岗位分工 | 高手的决策序列与隐含判断 |
| C 无先例 | 没有成熟做法，或这是 AI 时代才出现的工作 | 第一性原理 + 最小试跑 |

判不出来按 B。B 在访谈中一旦出现稳定分工，就升 A。

## 二、A 类：五张清单

还原完整不完整，用这五张表自检。缺一张，说明还停在"听说过"的层面。

| 清单 | 要回答 | 不合格的样子 |
|---|---|---|
| 角色谱系 | 谁参与，各自对什么质量负责 | 只有职称，说不出负责什么 |
| 工件链 | 谁交给谁什么，口头还是文件 | 交接靠"沟通"，没有实物 |
| 验收标准 | 什么东西会被打回，打回时说什么 | 只有"要专业""要注意质量" |
| 裁决权 | 冲突时谁拍板、依据是什么 | 都说"商量着来" |
| 反例 | 最糟的一次长什么样，事后加了什么规矩 | 一个真实反例都举不出 |

## 三、调研材料优先级（从实战到教科书）

越靠前越接近真实，越靠后越容易变成漂亮话。

1. **一线从业者的口述**：访谈、播客、幕后纪录片、行业论坛的吐槽帖；
2. **事故与返工记录**：被毙的稿、返工单、事故复盘——最能暴露验收标准；
3. **行业手册与标准**：制片手册、诊疗规范、工程规范——结构化，但偏教科书；
4. **招聘 JD**：职责边界写得最直白，适合快速画出角色谱系；
5. **百科与科普**：只用来补名词，**不要用来定流程**。

## 四、三证原则（防幻觉）

每条结论至少要有两证，缺证必须标「假设」：

| 证据 | 含义 |
|---|---|
| 来源 | 谁说的 / 哪份材料写的 |
| 案例 | 一件具体发生过的事 |
| 反例 | 一次具体的失败 |

缺任意一项 → 写「假设·待验证」，并放进试跑清单。**不许把假设写成事实。**

## 五、还原成功的四个判据

能答出来，才算还原到位：

1. 什么情况下，一个交付物会被打回？
2. 两个角色意见冲突时，谁拍板，凭什么？
3. 哪个交接点最容易丢信息（翻译损耗最大）？
4. 至少三个真实反例，各自的根因是什么？

## 六、B 类：没有分工，就还原"高手的决策序列"

不要硬凑部门。改问：

- 找 3 个以上高手的作品或复盘；
- 抽「他在什么信号下改了什么」：为什么这里停、为什么这里删、为什么这里加；
- 重点是**隐含判断**，不是步骤。步骤谁都会写，判断才是手艺。

产出形态是一串「信号 → 判断 → 动作」，不是角色表。

## 七、C 类：没有先例，就别一次设计十个单元

- 先做**最小可跑流程**（3 个单元以内），跑一个真实小任务；
- 用失败反推缺了哪个单元，而不是先想全再跑；
- 每轮只加一个单元，加完立刻试；
- 单元数量由试跑决定，不由想象决定。

## 八、常见失败

| 现象 | 根因 | 改法 |
|---|---|---|
| 把百科当流程 | 图和名词好找，实战难找 | 只信口述、返工记录、JD |
| 把职称当角色 | 抄了组织架构 | 改写成"对什么质量负责" |
| 只还原成功 | 成功案例好看 | 必须挖失败与打回 |
| 20 个角色却不知道谁拍板 | 没有裁决权这一栏 | 补冲突裁决表 |
| 全是"看情况" | 没追问看哪些情况 | 把"情况"拆成决策树分支 |

## 九、输出

填 `templates/profession-map.md`，一页纸。填不满就说明还原没做完，不要进入下一步。
