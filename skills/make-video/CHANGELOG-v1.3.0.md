# v1.3.0 — 全片禁止变焦 + 地图分级标注 + 克隆音色入口修正

这一版由三句用户原话驱动，全部来自同一个真实项目（`中国山脉与河流-mwft2w32`，3 分钟地理讲解片）：

> 「放大缩小的运镜能否取消掉，感觉在各个视频里这种效果都不好看」
> 「讲到什么地方的时候，能不能在对应地图上把对应地方的区域用动线、区域形状标注出来呢，现在就只有一个小点」
> 「视频应该用我的个人配音」

三条都不是调参能解决的，各自对应一处**结构性改造**。

## 1. no-zoom：全片禁止变焦（V-CAM-007）

**问题不是幅度，是「scale 有没有随时间变」**。只要变，观众就读成变焦——把幅度从 8% 调到 3%
只是让它更难察觉，不是消除。此前 `push-in` / `pull-out` / `dolly-in/out` / `crane-up/down` /
`punch-in` / `drift` 八个分支、以及 `coverage` 覆盖切，全都在改 `scale`。

改造：

| 位置 | 改法 |
|---|---|
| `camera.ts::waypointsFor` | 所有分支的 `scale` 字面量统一为 `SCALE_HOLD`（导出常量，默认 1.06），运动只由 `xPercent`/`yPercent` 承担 |
| `camera.ts::accumulate` | `coverage` 的 `scale` 折成 1；位移 ±6 / 旋转 ±1.5 保留（那是构图，不是放大） |
| `camera.ts::stateAt` | 输出 `scale: SCALE_HOLD` 恒定值 |
| `motion-lib.js::MV.camera` | 八个运镜分支全部改为纯位移；`zoom` 参数改成 `hold`（恒定过扫量），`travel` 可调行程 |

**语义保留**：`push-in` 变成「向主体方向平移」，`pull-out` 变成「背离主体平移」，词位没删
（删会破坏 `continuity.ts` 的 `CAMERA_VECTORS` 与三处测试的类型约束）。

**为什么 `SCALE_HOLD` 不是 1**：平移需要画面比窗口大，否则边缘露白。1.06 给出 3% 单侧余量，
2.2% 的 `DRIFT` 行程刚好落在余量内。

**机检判据**：`tests/composer.test.ts` 断言每个机位分段的 `from.scale === to.scale === 1.06`。
实测 18 镜 60 个分段全部通过。

## 2. 地图分级标注（V-CAM-008）

原实现只有 `marker()`——一个 8px 圆点 + 文字，16 处地标全用同一种表达。一屏十几个一样大的
圆点不是标注，是把地图当背景。现在按语义分三类：

| 语义 | 原语 | 画法 |
|---|---|---|
| **面** | `region()` | 闭合多边形 + 12-16% 半透明填充 + 虚线描边 + **质心注记** |
| **线/方向** | `flow()` | 折线 + 端点箭头（SVG `marker`）+ 流动虚线（`stroke-dashoffset` 动画） |
| **点** | `marker()` | 圆点 + 文字，一屏 ≤2 个 |

`flow()` 每条动线自带独立 `<defs>` 箭头（id 递增），避免多镜合成时 defs 冲突。

顶点按**真实边界经纬度**取（每 2-4 经度一顶点），文档里给了六块区域的实测顶点
（青藏高原 / 黄土高原 / 塔里木 / 四川 / 东北 / 华北平原）。

## 3. 克隆音色入口修正（重要）

`voice --shot sXX` 走的是 `MV_TTS` 缺省值（`auto` → edge-tts），**不会用** `personal/profile.json`
里的克隆音色，合成结果的 `voice.voice` 字段会是 `auto`。正确入口是：

```bash
node scripts/run-voice.mjs <project> --shot sXX
```

它把 qwen3 + `refAudio` + `promptText` 注入环境变量。**验收判据**：`project.json` 每镜的
`voice.voice` 必须不是 `auto`。

本次据此把 18 镜全部重录，`voice.voice` 统一为 `qwen3`。

## 4. 修掉三个真实渲染 bug（都不是配置问题）

| # | bug | 后果 |
|---|---|---|
| 1 | `<path>` 没包 `<svg>` | HTML 解析器把 `path` 当未知元素丢弃，**区域形状与动线从未渲染过**——上一版「地图主轴」实际只有底图 + 圆点 |
| 2 | `<div>` 塞进 `<svg>` 里 | 修好 #1 后色带整块消失（实测琥珀像素占比回落到 0.07%）。改为 `splitBody()` 按顶层标签分流：SVG 放 path/text，HTML 层放 div |
| 3 | 坐标系混用 | 百分比坐标配像素 `stroke-width` 会让描边粗细随宽高比变形。统一 `viewBox="0 0 1920 1080"` + 经纬度→百分比→像素单一路径 |

**机检方法**（写进 docs/14）：把场景渲染成 PNG，缩到 480×270 后统计像素——
琥珀色（`R>140 && G>90 && B<120 && R-B>60`）与青蓝色（`B>130 && G>110 && B-R>55`）。
正常值暖色 0.4-2.3%、冷色 0.1-0.6%；若两者都 <0.05%，几乎必然是上面 #1/#2 之一。

## 破坏性变更

**有，但只影响「期望画面放大」的存量项目**：升级后所有镜头的 `scale` 恒定在 1.06，
原先靠 `push-in`/`dolly-in` 做的推镜会变成平移。

- 想恢复放大：`visual.params.cameraHold` 只能调过扫量，**无法恢复时变缩放**（这是刻意的）
- `MV.camera` 的 `zoom` 参数已改名 `hold`（旧调用不会报错，`zoom` 被忽略）
- 无需改 `project.json`；`coverage[].scale` 保留但不再生效
