# 真实素材 × 地图主轴：地理讲解类影片的制片经验

> 沉淀自 `中国山脉与河流-mwft2w32`（3 分钟中国山脉河流讲解片）。
> 来源灵感：I-20261114-01（找真实素材的经验沉淀）、I-20261114-02（应围绕真实地图展开）。

## 一、最重要的一条：先决定「叙事骨架」再找素材

**错误做法（本任务第一版就是这么错的）**：把讲稿切成 18 个镜头，逐镜找一张「好看的实景图」，做成拼贴卡片。
结果：每镜都有一张真实照片，但**地图这个真正的主角消失了**，观众看不出「天山在哪」「几字弯在哪」。
用户的原话是「不是应该围绕真实地图去展开讲吗，讲到哪里，在地图具体的位置去标注」。

**正确做法**：地理类题材的骨架是**一张真实底图 + 精确落点标注 + 当镜实景特写**，三者各司其职：

| 承担 | 用什么 | 为什么 |
|---|---|---|
| 空间关系（在哪、怎么走） | 真实地形底图 + 代码画的路径/标注 | 只有地图能表达位置与走向 |
| 证据（这东西真的长这样） | 真实摄影素材 | 只有照片能建立可信度 |
| 运动与注意力 | 代码动效（画线、counter、高亮） | 只有代码能精确控制节奏 |

**判据**：如果把这些实景照片换成纯色块，观众还能听懂吗？如果不能，说明照片在承担证据而不是装饰；
反过来，如果把地图换成纯色块就彻底听不懂了，说明骨架对了。

## 二、真实地图怎么拿到，以及怎么在地图上精确落点

### 2.1 底图：Wikimedia 的地形图系列

`China edcp relief location map.jpg`（1968×1567，CC BY-SA 3.0，Uwe Dedering）
是维基 `Module:Location map/data/China` 指定的地形底图，全球同类地图几百张，都遵循同一套定位约定。

**下载通路（本机实测）**：`commons.wikimedia.org` / `upload.wikimedia.org` 直连全部超时，
唯一可行的是 wsrv.nl 的 `Special:FilePath` 形式，且**文件名里的 `%20` 必须再被 `encodeURIComponent` 编码一次**（变成 `%2520`），否则 404：

```
https://wsrv.nl/?url=<encodeURIComponent("commons.wikimedia.org/wiki/Special:FilePath/China%20edcp%20relief%20location%20map.jpg")>&w=2400&output=jpg&q=92&cb=<随机数>
```

偶发 404 时换 cache-buster（`cb` 随机）重试 1-3 次即可。

### 2.2 落点：直接用维基的投影公式（不要自己猜经纬度到像素的映射）

维基的 `Module:Location map/data/China` 里存的就是把经纬度映射到图像百分比的公式（equirectangular 变体）：

```js
const D = Math.PI / 180;
function proj(lat, lon) {                    // 返回图像内百分比坐标 [x%, y%]
  const x = 50 + 116.80932603407057 * ((1.9996655301850468 - lat * D) * Math.sin(0.5867115434267053 * (lon - 104) * D));
  const y = 50 + 1.256383 * 116.80932603407057 * 0.02641006622571962
    - 1.256383 * 116.80932603407057
      * (1.3713469994670882 - (1.9996655301850468 - lat * D) * Math.cos(0.5867115434267053 * (lon - 104) * D));
  return [x, y];
}
```

含地图的图像尺寸比 `H/W = 1567/1968 = 0.7962`，据此把图像百分比换算到舞台的 16:9 坐标（舞台高度按图像宽度的 56.25% 记）。

**已验证**：北京 / 乌鲁木齐 / 拉萨 三点经渲染截图反解，误差 ≤ 0.04°（≈4 km，受 9px 检测块限制）。
验证方法：在地图上按经纬度打彩色方块 → 无头 Chrome 截图 → 找色块中心 → 反解回经纬度 → 与输入对比。

### 2.3 缩放与对准：把某个地标放到画面中心

```js
function frame(zoom, lat, lon) {              // 让 (lat,lon) 落在画面中心
  const [cx, cy] = proj(lat, lon);
  const left = 50 - zoom * cx;                                  // 图上元素 left%
  const topUnits = 28.125 - zoom * 0.7962 * cy;                 // 28.125 = 56.25/2
  const to = (lat2, lon2) => {                                  // 任意经纬度 -> 舞台坐标
    const [px, py] = proj(lat2, lon2);
    return [left + zoom * px, ((topUnits + zoom * 0.7962 * py) / 56.25) * 100];
  };
  return { zoom, left, topPct: (topUnits / 56.25) * 100, to };
}
```

地图元素定位：`.map { position:absolute; left:<left>%; top:<topPct>%; width:<zoom*100>% }`，
内部 `img { width:100%; height:auto }`。之后所有标注都可以用 `frame.to(lat, lon)` 拿到舞台百分比，**不用手量像素**。

## 三、真实照片素材：检索与下载的可行通路

| 环节 | 可行 | 不可行（实测，勿重试） |
|---|---|---|

| 图片二进制 | `wsrv.nl/?url=commons.wikimedia.org/wiki/Special:FilePath/<文件名>&w=2000&output=jpg` | `upload.wikimedia.org/...` 完整路径（wsrv 返回 404）、Openverse、r.jina.ai 取二进制 |

| Pexels 官方 API | 需 `MAKEVIDEO_PEXELS_API_KEY`，未配置时 `stock` 命令不可用 | —— |

**许可纪律**：每张素材入库必须带 `sourceUrl` + `license` + `credit` 三个字段，
`add-material --url --license --credit` 一次写全；入库后统一核对这三个字段无空值。

## 四、素材「真的进了画面」怎么证明（不是靠看）

拼接类场景（地图上一角放一张实景卡）容易出问题：图片路径错、被裁掉、被暗化到看不见。
用**数值闭环**代替目测：按卡片的内联定位裁出成片对应区域，与素材原图比较灰度直方图/均值。

```
成片中 t 时刻、卡片矩形 (x,y,w,h) 的灰度均值  ÷  素材原图的灰度均值 ≈ 0.76–0.91
```

这个比值区间稳定意味着「照片在、只是叠了暗化滤镜」（本任务 18 镜全部落在此区间）。
若某镜比值趋近 0 或裁剪区全黑 → 图片没加载/被裁出画面，必须修。

同理适用于验证「成片不是首帧定格」：抽取多个时间点的低分辨率帧，比较均值/直方图的分布散度。

## 五、场景校验器（make-video 的 V-SCENE 系列）踩坑清单

| 规则 | 坑 |
|---|---|
| V-SCENE-005 对位铁律 | HTML 全文（**含 CSS/JS 注释**）里任何 ≥4 字与旁白重合的中文串都报 error。写画面文案前先把旁白去标点后按 4 字切片比对；标题换说法（"还是吃饭"→"换成什么"），不要照抄旁白。 |
| V-MOT-023 | `actionSheet.requiredPrimitives` 列的每个原语（形如 `MV.counter`）都必须真实出现在 HTML 里，缺一个就 `adopted:false`。 |
| V-MOT-021 | 每镜必须至少一处 `MV.motifLoop(`（画布类豁免）。 |
| duration 档位 | 只允许 150-200 / 200-400 / 400-800 / 300-600 / 1200-2000 ms 五档。 |
| 转场 | 风格包的 `transitions` 词表默认只有 `dissolve`；导演声明了 `hard-cut`/`whip-pan`/`smash-cut` 就要在 `project.style.overrides.transitions` 里显式加入，校验器拒绝静默回退。 |

**批量自检**：写一个脚本直接 `import { validateSceneFile } from '<skill>/dist/core/validators/scene.js'`，
对 18 个 HTML 一次性跑完并打印缺失原语——比逐镜调 CLI 快一个数量级（CLI 单次约 2-4 秒）。

## 六、流程上的时间坑

- `voice` 全量跑会撞工具 60 秒上限（K502）；**逐镜 `voice --shot sXX`** 每镜 1-3 秒即可。
- 用**克隆音色**时不能只调 `voice --shot`：那样走的是 `MV_TTS` 缺省（`auto`→edge-tts），
  合成出来 `voice.voice` 字段会是 `auto`。正确入口是 `node scripts/run-voice.mjs <project> --shot sXX`，
  它会把 `personal/profile.json` 的 `voice` 段（qwen3 + refAudio + promptText）注进环境变量。
  **验收判据**：`project.json` 里每镜 `voice.voice` 必须不是 `auto`；是 `auto` 就说明没用克隆音色。
- `render` 必然超过 60 秒：用 detached 子进程 + 日志文件跑，不要在前台等。
- 渲染异常中断会留下 `.render.lock`，下次渲染前要先删掉。
- 无头 Chrome 截图验证场景时，**中文路径必须 `pathToFileURL()`**，否则 Chrome 找不到文件，且要带 `--allow-file-access-from-files` 才能读 `../canvas/*.jpg`。

## 七、地图上的「标注」到底该画什么（2026-11-15 升级）

用户看过第一版后的原话：「讲到什么地方的时候，能不能在对应地图上把对应地方的区域用
动线、区域形状标注等方式画出来呢，现在就只有一个小点」——**一屏十几个同样大小的圆点，
不是标注，是把地图当背景**。

按语义分三类，各有专用表达（`genmap.mjs` 里的 `region()` / `flow()` / `marker()`）：

| 语义 | 原语 | 画法 | 用在 |
|---|---|---|---|
| **面**（这一片是什么） | `region()` | 闭合多边形 + 10-16% 半透明填充 + 虚线描边 + **质心注记** | 青藏高原、黄土高原、塔里木盆地、四川盆地、东北/华北平原 |
| **线/方向**（水往哪流、山往哪走） | `flow()` | 折线 + 端点箭头 + 流动虚线（`stroke-dashoffset` 动画） | 黄河、长江、珠江、三条横向山系、沿海山系 |
| **点**（就是这个地方） | `marker()` | 8px 圆点 + 文字 | 壶口、夔门、宜宾、唐古拉；**一屏 ≤2 个** |

区域顶点要按**真实边界经纬度**取（每 2-4 经度一顶点），不要随手画个框——观众认得出青藏高原
的形状，画歪了比不画更糟。文档里给了六块区域的实测顶点，可直接复用。

### 两个必须知道的渲染陷阱（都实际踩过）

1. **`<path>` 不包 `<svg>` 就完全不渲染。** HTML 解析器把 `path` 当未知元素丢弃，
   于是区域形状与动线**从未出现在画面上**——上一版「地图主轴」其实只有底图 + 圆点，
   线一条都没显示。所有 SVG 图元必须包一层 `<svg viewBox=...>`。
2. **`<div>` 塞进 `<svg>` 里同样不渲染。** 反过来也成立：色带、卡片锚点这些 HTML 元素
   不能和 path 混在同一层。正确做法是分两层：`<svg>` 放 path/text，HTML 层放 div。
   本仓库的 `page()` 用 `splitBody()` 自动按顶层标签分流。

坐标系：`viewBox="0 0 1920 1080"` + `preserveAspectRatio="none"`，所有经纬度先换成百分比
再乘 19.2/10.8 转成像素。这样 `stroke-width`、字号、`stroke-dasharray` 都是**像素**语义，
不会随宽高比变形。

### 机检「区域和动线真的画出来了」

不要靠看图下结论（上一版就是这么漏掉的）。把场景渲染成 PNG，用 ffmpeg 缩到 480×270 后
统计像素：

- **琥珀色占比**：`R>140 && G>90 && B<120 && R-B>60` → 区域描边 / 动线 / 高亮
- **青蓝色占比**：`B>130 && G>110 && B-R>55` → 水系动线

实测正常值：暖色 0.4%-2.3%、冷色 0.1%-0.6%；若某镜两者都 <0.05%，几乎必然是
「SVG 没包 / div 混进 svg」这两个陷阱之一。
