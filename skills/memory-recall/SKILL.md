# 分层记忆召回（Q 轮 Phase 1）

本仓的「项目层/语义层」记忆用现成机制落地：`SYSTEM.md` + `skills/<name>/references/`（语义记忆）与 `ledger/`（情景记忆）。本技能规定**何时读、读几条、怎么裁**，避免把文档全文灌进模型上下文（docs/05-评测与记忆四层设计.md:72,76-90,115-134）。

## 何时触发

- 任务涉及本仓历史决策、约定、迭代轨迹，且当前上下文没有明确结论；
- 需要先判断「已评估不做」「已否决方案」，防止重复尝试；
- 需要跨会话复用项目级事实，但不需要逐字引用原文。

## 硬预算（不可放宽）

1. 一次召回 **≤5 条**条目；
2. 注入模型的总字符 **≤25KB**（约 6000 汉字）；
3. 超限必须**报错并要求精简索引**，不得静默截断后当作完整记忆使用；
4. 只返回摘要级条目（标题 + 路径 + ≤200 字要点），**不返回全文、不返回 base64/附件、不返回 api_key/token/password**；任何疑似密钥字段一律视为不可见，不复述、不落盘。

## 执行顺序

1. 先用 `grep` / `symbols_search` 在 `docs/self-evolution/00-PLAN.md`、`skills/*/references/`、`ledger/` 定位候选标题（不整文件读取）；
2. 按「与当前任务的时间/模块相关度」排序，取前 ≤5 条；
3. 逐条用 `read_file` 带 `offset/limit` 只读命中段落，压缩成「路径 + 一行结论」；
4. 拼装前测量字符数，超 25KB 立即停止并回报「索引需精简」；
5. 把拼装结果作为**派生视图**注入当前推理，不得写回 `runtime/`、`config.json` 或 `plugins/memory`。

## 边界

- 真相源仍是磁盘文件；本技能只做派生，不另立事实源（与 trace 是 UI 真相源同理）。
- 需要逐字核对契约/代码时走 `read_file` 原文，不走摘要。
- 服务端会话消息与 trace 的召回由 memory 插件 `memory.recall` op 提供（Phase 2），本技能不替代插件。

## 验收标准

一次召回合格，当且仅当下面四条全部可核：

1. **条数达标**：返回条目数 ≤5，且每条含「路径 + 一行结论」两要素——只有结论没路径不算（无法回溯）。
2. **预算达标**：注入文本实测字符数 ≤25KB；超限时**必须**输出「索引需精简」并要求精简，不得截断后静默继续。
3. **无泄漏**：结果中不含 api_key / token / password 明文，不含附件 base64。可用 `grep -Ei "api[_-]?key|token|password|base64"` 对拼装结果自检，命中即判不合格。
4. **未越权写盘**：召回过程对 `runtime/`、`config.json`、`plugins/memory` 零写入。可用 `git status --porcelain` 确认这三处无改动。

反例（一律判不合格）：把整份参考文档全文贴进上下文；返回 6 条以上；超 25KB 后自行截断当作完整记忆；把召回结论写回 `plugins/memory`。
