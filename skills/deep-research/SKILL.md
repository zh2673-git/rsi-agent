# 深度研究（账本驱动，不是多问几轮）

本技能解决的是**研究这件事的持久状态**，不是「再多加一个搜索工具」——`web_search` /
`web_read` / `task` 并行子代理本来就够跑循环。缺的是三件：

1. 撞预算墙后**从哪继续**（`CHAT_BUDGET_SECS` 缺省 900s，到界即收尾）；
2. 报告里每条断言**有没有出处**（来源只以胸牌流向前端，跑完散在 trace 里）；
3. 读了哪些**没用上**（白花的 token）。

三件都由 `scripts/research.py` 落盘解决。

## 何时用

- 「帮我深度调研 X / 多源交叉验证 / 写一份带出处的报告」
- 「上次那个研究做到哪了 / 继续」
- 任何**产出物会被别人拿去核对**的调研（有无出处是可机检的）
- 不适用：一次性问答、「查一下某个 API 签名」这种——直接 `web_search` 就好，别建账本

## 铁律四条

### 1. 先立计划，再开搜

```
python scripts/research.py new "<主题>" --questions "子问题1" "子问题2" ...
```

子问题要**可独立回答**（「A 的定价」而不是「A 的一切」）。计划落 `.rsi/research/<主题>/plan.json`，
这是断点恢复的唯一载体——**不立计划就开搜，等于把进度存在上下文里，撞墙即全废**。

### 2. 每读完一个来源，立刻记账

```
python scripts/research.py --topic "<主题>" add --url "<url>" --title "<标题>" --quote "<原文摘录>"
```

`--quote` 必须是**原文摘录**（会被 `check` 当作事实凭据），不是自己的概括。
账本 append-only——来源是事实，事实不该被覆盖。

### 3. 每完成一个子问题，立刻落结论

```
python scripts/research.py --topic "<主题>" done <idx> --note "<一句话结论>"
```

结论要能独立读懂（下一轮 `resume` 只会给你这一行，不会给上下文）。

### 4. 写报告时每条事实性断言带 `[S7]`

写完**必须**机检：

```
python scripts/research.py --topic "<主题>" check outputs/<报告>.md
```

退出码 0 = 全过；1 = 有问题。三条判据：

| 判据 | 抓什么 |
|---|---|
| 引用的 `[S*]` 在账本里存在 | **编造引用** |
| 每条账本条目至少被引用一次 | **读了没用**（该删条目或该用它） |
| 事实性段落无引用标记 | **无出处的断言** |

「事实性段落」= 长度 ≥30 字的正文/列表项；标题、代码块、表格、引用块不算。

## 撞墙了怎么办

预算到界会被 `budget_stop` / `wrap_up_once` 收尾，本轮结束。**下一轮直接**：

```
python scripts/research.py --topic "<主题>" resume
```

它给「下一个待办子问题 + 已有结论」。**不要重新调研已 done 的部分**——那是在烧同一份预算两次。

## 并行子问题（`task` 子代理）

`task` 子代理并行跑，但**它不写父的账本**：子代理搜到的东西如果没进 `answer` 就丢了。
所以派活时必须在任务描述里写死：

> 先 `python scripts/research.py --topic "<主题>" add ...` 记账，再把结论写进你的 answer。

子代理有 `bash`，账本对它可达。这一条不改代码，但决定并行研究是「真并行」还是「并行然后丢细节」。

## 深浅分级（别一律开满）

| 深度 | 子问题数 | 来源数 | 适用 |
|---|---|---|---|
| 快查 | 1-3 | 2-5 | 一个事实/一个 API 怎么用 |
| 标准 | 4-8 | 8-20 | 选型对比、机制调研 |
| 深研 | 9-20 | 20-60 | 需要交叉验证、要能反驳主流说法 |

来源少于子问题数，基本可以断定是「一段文字编到底」——`check` 的「读了没用/无出处」会暴露它。

## 验收（可机检，不靠自我感觉）

一份深度研究交付合格的判据，全部可由命令判定：

| # | 判据 | 怎么验 | 通过标准 |
|---|---|---|---|
| 1 | 计划存在且全部完成 | `python scripts/research.py --topic <t> plan` | 子问题全部 `[x]` |
| 2 | 引用完整 | `python scripts/research.py --topic <t> check outputs/<报告>.md` | 退出码 0 |
| 3 | 无编造引用 | 同上，看 `missing` 字段 | `[]` |
| 4 | 无「读了没用」 | 同上，看 `unused` 字段 | `[]` |
| 5 | 无无出处断言 | 同上，看 `uncited_paragraphs` | `[]` |
| 6 | 来源密度合理 | `list` 的「N 条尚未被引用」 | 未引用数 = 0 |
| 7 | 断点可恢复 | `resume` 输出「下一个 + 已有结论」 | 两段都有内容（中途）或明确「全部完成」 |

**第 3/4/5 条就是 `check` 的三条判据**——它们不是「建议」，是退出码。所以「我认为报告写得有出处」
不是验收，`check` 退出码 0 才是。

反例（会被抓到）：报告引用了 `[S9]` 但账本只有 S1/S2 → 判据 3 红；账本有 12 条来源但报告只用了
5 条 → 判据 4 红；一段 200 字的结论没有任何 `[S*]` → 判据 5 红。

## 反面清单

- **不要**边搜边写终稿：先 plan → 逐个 done → 最后成稿，否则改一次结论要重写整篇。
- **不要**用概括代替 `--quote`：`check` 时它无法自证。
- **不要**为了让 `check` 过而给每句硬塞引用：`[S1]` 挂在不相干的句子上，人一眼看得出，机器看不出——这是唯一能骗过 `check` 的方式，也是唯一没有价值的方式。
- **不要**把研究目录当产物目录：`.rsi/research/` 是账本（派生视图可重建），交付物落 `outputs/`。
